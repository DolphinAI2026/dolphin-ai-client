# 睿鲸 Coding 测试用例

**版本**: v1.0
**日期**: 2026-04-26
**范围**: 睿鲸 Coding 验证 aPaaS 自开发组件、页面、接口及相关工作区能力
**入口**: `/coding?type=apaas-custom-dev`、智能搭建派发到 Coding、Web IDE 睿鲸 AI 扩展

## 1. 测试目标

验证睿鲸 Coding 能正确识别自开发类型，创建或复用工作区，通过 Chat 与 IDE 完成代码生成、迭代、构建、预览、下载、上传平台和历史恢复。

重点覆盖三类 P0 产物：

| 类型 | 示例 | 核心验收 |
| --- | --- | --- |
| 表单组件 | 风险等级选择器、证照到期提醒组件 | 组件配置、编辑态、只读态、校验、i18n、打包 |
| 自开发页面 | 供应商风险看板、待办列表页面 | 页面路由、`this.$request`、权限、图表或表格交互 |
| 后端接口 | 风险汇总 REST 接口 | SpringBoot 包名、`/custom` 路径、白名单、Maven 打包 |

## 2. 前置条件

| 项目 | 要求 |
| --- | --- |
| 服务 | Builder 前后端、code-server 或内置工作区能力可用 |
| 账号 | 已登录，具备自开发包上传和应用高级设置权限 |
| 模型 | Coding 模型可用，Web Chat 与 IDE 使用同一模型配置 |
| aPaaS 应用 | 准备一个测试应用，包含供应商、风险事件等基础表单 |
| 工作区命名 | 使用 `tc-ruijing-YYYYMMDD-*`，避免覆盖真实工作区 |
| 平台发布 | 上传自开发包前确认目标为测试租户和测试应用 |

## 3. 测试数据

### 3.1 表单组件需求

> 开发一个双端表单组件“供应商风险标签”。在编辑态根据风险等级显示不同颜色标签，支持必填校验；只读态展示标签和说明；移动端保持可读；组件值保存为风险等级编码。

### 3.2 自开发页面需求

> 开发一个供应商风险看板页面。页面顶部有风险等级筛选和日期范围筛选，中间展示风险事件列表，右侧展示风险等级统计图。点击列表行打开系统详情抽屉。

### 3.3 后端接口需求

> 开发一个后端接口 `/custom/supplier/risk-summary`，返回各风险等级供应商数量和近 30 天风险事件数量。包名以 `com.xdap.tc` 开头，实现白名单注册，支持 Maven 打包。

## 4. 通过标准

| 编号 | 标准 |
| --- | --- |
| AC-01 | 自开发类型识别正确，组件、页面、接口不会混淆 |
| AC-02 | 工作区模板与类型匹配，关键文件存在且命名符合 aPaaS 规范 |
| AC-03 | Chat 与 IDE 共享同一工作区和上下文，刷新后可恢复 |
| AC-04 | 生成代码能通过对应构建或静态校验 |
| AC-05 | 上传平台或导出包时，产物完整且不包含无关临时文件 |
| AC-06 | 失败场景能给出可执行修复建议，而不是只返回模型原文 |

## 5. 类型覆盖矩阵

| 优先级 | 类型 | 项目类型 | 需要覆盖 |
| --- | --- | --- | --- |
| P0 | 双端表单组件 | `form-component-dual` | PC 编辑/只读、移动编辑/只读、共享配置 |
| P0 | Web 自开发页面 | `form-page` | 路由、页面入口、请求、权限、弹窗 |
| P0 | 后端自开发接口 | `backend-api` | Controller、Service、AllowUrlManage、Maven 包 |
| P1 | PC 表单组件 | `form-component` | 仅 PC 组件兼容旧项目 |
| P1 | 自定义列表视图 | `form-list` | listEngine 入参、列表渲染、操作事件 |
| P1 | 自定义布局 | `layout` | LayoutEngine 约束 |
| P1 | 前端插件 | `plugin` | admin/app/mobile 入口和 i18n |
| P2 | 脚本、弹窗、样式 | `script` / `ui-style` | 作为边界与回归补充 |
