# Vibe Coding 测试用例

**版本**: v1.0
**日期**: 2026-04-26
**范围**: Vibe Coding 0-1 开发全代码应用、1-N 迭代已有全代码应用
**入口**: `/vibe-coding`、`/coding?type=full-code`

## 1. 测试目标

验证 Vibe Coding 作为全代码开发入口，能完成 Git 仓库导入、任务登记、文件浏览、IDE 进入、Agent 分析，并在沙箱能力接入后继续完成 0-1 应用开发和 1-N 迭代。

当前基线能力分层：

| 层级 | 能力 | 测试定位 |
| --- | --- | --- |
| 当前已具备 | 工作区创建、公开/私有 HTTPS Git 导入、列表、详情、文件读取、IDE URL | P0 必测 |
| 当前占位或后续 | 沙箱执行、依赖安装、测试、预览端口、自动改代码、提交 PR | 作为目标验收用例保留 |

## 2. 前置条件

| 项目 | 要求 |
| --- | --- |
| 服务 | Builder 前后端可访问，Vibe Coding 路由已注册 |
| Git | 本机或服务端环境有 `git` 命令，能访问公开 GitHub/GitLab 仓库 |
| 账号 | 已登录，工作区按当前用户隔离 |
| Web IDE | 如需验证真实 IDE，需配置 `CODE_SERVER_BASE_URL`；未配置时按降级逻辑验收 |
| 私有仓库 | 使用测试 Token，Token 只用于本次导入，不写入文档或日志 |
| 仓库命名 | 使用公开样例仓库或测试组织仓库，不使用生产仓库 |

## 3. 测试数据

### 3.1 公开仓库导入

仓库：选择一个公开 HTTPS 仓库，例如 `https://github.com/<test-org>/<public-demo>.git`

任务：

> 分析项目结构，找出启动命令、测试命令和主要业务入口。

### 3.2 私有仓库导入

仓库：测试组织下的私有仓库。
Token：只给 read 权限，验证导入后立刻清空输入框和日志脱敏。

任务：

> 导入后先分析代码结构，不要自动安装依赖或执行仓库代码。

### 3.3 0-1 全代码应用目标

目标应用：`TCOnlineCoding_供应商门户`

需求：

> 从空项目创建一个供应商门户应用。包含供应商列表、风险事件列表、风险等级统计、详情页和基础登录占位。技术栈使用 Vue 3 + Vite，提供本地预览和基础单元测试。

### 3.4 1-N 迭代目标

基于已有供应商门户仓库继续迭代：

> 在首页新增风险看板区块，增加风险等级筛选；修复风险事件列表空数据展示；补充测试；通过预览确认后提交 PR。

## 4. 通过标准

| 编号 | 标准 |
| --- | --- |
| AC-01 | 工作区创建、导入、列表、详情和文件读取接口权限正确 |
| AC-02 | 只允许 HTTPS Git 地址，不允许 localhost、内网或带凭据 URL |
| AC-03 | 私有仓库 Token 不持久化、不明文显示、不出现在工作区 README |
| AC-04 | 仓库导入后能生成文件摘要，`.git`、`node_modules` 等目录不进入预览清单 |
| AC-05 | 导入成功后才能进入 IDE 或内置工作台；导入失败有可操作提示 |
| AC-06 | 目标能力接入后，0-1 和 1-N 都必须有计划、diff、测试、预览、Git 交付闭环 |

### 11.4 结论

Vibe Coding 当前已具备的控制面能力通过 smoke：认证、工作区创建、公开 Git 导入、失败提示、列表筛选、文件读取、路径防护、IDE URL 生成、内置工作台和基础 Agent 摘要均可用。0-1 全代码开发和 1-N 迭代仍属于后续沙箱 Agent 能力，当前不能按“已完成”验收。
