## 一、系统现状的实事求是描述

跑通了三条路径,但每条都有"看着完整、其实漏一截"的问题。

| 路径 | 入口 → 终点 | 真实状态 |
|------|------------|----------|
| **文档建模** | `Landing.vue` 上传 MD → `routes/applications/docs.py:66` → `doc_pipeline.py` → `generator_v2.py` 5 phase → aPaaS API | **能跑完**,但无确认 gate、无事务、权限阶段静默吞错 |
| **对话搭建** | `ChatPage.vue` → `routes/chat.py:524` → 三分支(高规范文档/silent generator/普通聊天)→ 同一个 generator_v2 | LLM 出 config 用正则抓(`chat.py:415`),三分支判定逻辑藏在 chat.py 里,**没有独立的需求收集 state machine** |
| **Online Coding** | `CodingPage.vue` → `/harness/coding/pipeline` → `coding/vibe_agent.py` httpx 循环 → `coding/workspace.py` code-server 工作区 → publish | **18 个场景生成器都在**,但 agent 是"一次性写代码不验证、不开浏览器看",`browser_service.py` 完整实现却**从未被 agent 调用** |
| 增量更新 | `VersionHistory.vue` + `api/incremental.ts` → `routes/incremental_update.py` → `IncrementalExecutor.execute_diff` | **真在用**(initial agent 报告漏判此项,后续核对修正) |

## 二、关键真相校正(verified)

1. **`vibe_agent` 不用 claude-agent-sdk**
   整个文件除了一个 URL 字符串替换没有任何 SDK 引用。`routes/coding.py:39-46` 的 `try/except ModuleNotFoundError` 是**防御性死代码**——即使 SDK 没装,系统照常工作,因为根本没用。

2. **"AI 看浏览器效果"是 PR 话术**
   `coding/browser_service.py` 有 Playwright 实现,有 REST 路由,**就是 agent 工具表里没有它**。

3. **`/harness` 是迁移产物,新旧并存**
   `routes/harness.py:158` 注释直白写着"替代旧的 /coding/auto-pipeline"。但 `frontend/src/api/coding.ts:177` 旧端点还在。

4. **uvicorn 单 worker 是被迫**
   状态散在进程内存(workspace 字典、proxy 状态),不是性能选择——这从最近 commit 消息(`后端 uvicorn 改单 worker，避免 iframe 代理跨 worker 丢状态`)反推。

5. **`.mdc` 规则不是 prompt-injected**
   `coding/workspace.py:524` 把它写成工作区文件,然后在 `vibe_agent.py:971` 的 system prompt 里"嘱咐 LLM 自己去读"。LLM 不读就完蛋,这是脆的。

6. **dead code 实锤(grep 验证)**
   - `doc_parser.py` 零引用(546 LOC)
   - `doc_differ.py` 零引用(277 LOC)
   - `doc_text_differ.py` 也零引用
   - `app/skills/` 子系统 ~1171 LOC 全部 scaffold,只有自身 test 文件引用

## 三、优化建议清单(按 ROI 排序)

### P0 — 直接卡产品价值,必须修

| # | 问题 | 证据 | 建议 |
|---|------|------|------|
| 1 | **Vibe Agent 无 verify-fix 闭环**:tool_calls 为空就退出,生成错了不修 | `coding/vibe_agent.py:316-320` | 接 `coding/verifier.py` / `validator.py` / `form_component_editor` 的检查结果回灌成新一轮 turn,加 `max_fix_iters=3` |
| 2 | **AI 不"看"运行效果**:浏览器服务造好不接 | `coding/browser_service.py` 全文 vs vibe_agent 工具表 | 把 `screenshot` / `navigate` / `get_console_errors` 注册进 `coding/tools.py`,让 agent 在 `start_serve` 后强制截图回传 |
| 3 | **部署无事务**:5 phase 串行,partial fail 应用卡死 | `generator_v2.py:1107-1110`、`generator_v2.py:1241` "权限失败不阻断" | 加 saga 模式:每个 phase 记 compensating action(删 role/删 model/删 form),失败按反序回滚 |
| 4 | **没有部署前确认 gate**:upload-doc 一进就 persist,Generate.vue 进度条不暂停 | `routes/applications/docs.py:66-96`、`routes/applications/generate.py:94-117` | parse 完返回 preview,前端 explicit "确认部署" 按钮再触发 generate |
| 5 | **silent failure 模式**:权限失败/AI fallback 强制开启都被吞 | `generator_v2.py:1241`、`doc_pipeline.py:26` `_FALLBACK_TO_AI=True` 硬编码 | 失败要 surface 到前端 toast + DB 记 failed step;FALLBACK 改 settings 可控 |
| 6 | **agent 教 LLM 留 TODO 占位符** | `coding/vibe_agent.py:1214` prompt 中"// TODO: 替换为实际 API" | 改成强制 agent **要么真接 API、要么标 stub 状态返回前端**让用户选,不要把烂尾代码丢给用户 |

### P1 — 架构债务,半年内必清

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 7 | **三套部署执行器并存**:`step_executor.py` / `generator_v2.py` / `generation_steps.py` 互相重复 | 改一个动作要改三处,极易偏差 | 确认 generator_v2 是 live(已确认),删 step_executor 和 generation_steps 中重复部分 |
| 8 | **死代码 ~2000 LOC** | 阅读成本暴涨,新人误读 | 删:`doc_parser.py`(546)、`doc_differ.py`(277)、`doc_text_differ.py`、`app/skills/` 三件(~1171)、`migrate_multi_tenant.py` 移到 `scripts/migrations/` |

## 四、一句话诊断

> 这个系统**没有"功能差很多"——而是每条主线都做到了 70%、剩下 30% 是该系统真正出价值的部分**(回滚、自验证、视觉反馈、确认门、状态外置)。看起来 60% 的代码量在做架构,40% 在做功能,但里面**两到三套并存的实现**和 **2000+ LOC 死代码**把"完成度"稀释成了"杂乱"。
