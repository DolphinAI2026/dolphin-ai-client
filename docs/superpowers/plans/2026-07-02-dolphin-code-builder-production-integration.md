# Dolphin Code Builder Production Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the apaas-builder-ai Code mode backed by d-ai-code Control Plane and agent-runtime as a production-safe, observable, rollbackable integration.

**Architecture:** apaas-builder-ai remains the shell owner: it owns login, mode routing, app catalog presentation, outer rail grouping, and the iframe proxy. d-ai-code remains the runtime owner: Control Plane owns applications, workspace open, sandbox lifecycle, launch tokens, runtime session APIs, and the embedded Builder UI. The browser never talks to upstream sandbox URLs directly; it loads `/api/code-runtime/{shellSessionId}/builder?...` through ai-builder, which exchanges a short-lived `dolphin_token` for a scoped proxy cookie and streams all runtime traffic through the same shell proxy.

**Tech Stack:** FastAPI, SQLAlchemy async, Vue 3, Vue Router, Pinia, Vitest, Playwright, Spring Boot 3.5, PostgreSQL, Redis, Kubernetes/Helm, d-ai-code agent-runtime React/Vite Builder.

## Scope Boundaries

- Application fetching remains Builder -> `codeRuntimeApi.listApplications()` -> Control Plane `/api/applications`.
- Shell session create/open remains Builder `/code/sessions/from-external-app` and `/code/sessions/{id}/open`.
- Runtime session list/create/activate/delete remains d-ai-code runtime `/api/agent/sessions*`, reached through Builder proxy.
- Authentication mode is not redesigned in this plan. Launch uses the existing ai-builder auth context plus `DOLPHIN_CODE_CONTROL_PLANE_TOKEN` when configured.
- Sandbox selection, title generation, model selection, and d-ai-code runtime business behavior remain owned by d-ai-code.
- UI unification work already done in d-ai-code remains a dependency; this plan only calls out release gates for it.

## Token Model

- `DOLPHIN_CODE_CONTROL_PLANE_TOKEN`: backend-to-Control-Plane bearer token. It is used by ai-builder backend for listing Code apps and opening workspaces when present. This token is never sent to the browser.
- Delegated identity headers: ai-builder sends `X-AI-Builder-Delegated-User-Id`, `X-AI-Builder-Delegated-Tenant-Id`, `X-AI-Builder-Local-User-Id`, `X-AI-Builder-Local-Tenant-Id`, `X-AI-Builder-Delegated-Username`, `X-AI-Builder-Delegated-Display-Name-B64`, and `X-AI-Builder-Shell-Session-Id` to Control Plane on workspace open. Control Plane only honors delegated user identity when the bearer token resolves to an ADMIN user.
- `dolphin_token`: short-lived iframe entry token generated by ai-builder in `create_embed_token()`. It authorizes one browser entry into `/api/code-runtime/{shellSessionId}/builder` and is stripped from the URL by a 307 redirect.
- `dolphin_code_runtime_{shellSessionId}` cookie: ai-builder proxy cookie issued after `dolphin_token` validation. It is HttpOnly, path-scoped to `/api/code-runtime/{shellSessionId}`, and gates subsequent iframe/proxy requests.
- Sandbox runtime API token: internal d-ai-code token mounted into the sandbox by Control Plane. It authorizes sandbox -> Control Plane calls and is not a browser or Builder frontend credential.

### Browser -> Builder Proxy

Initial iframe URL generated by ai-builder:

```text
/api/code-runtime/{shellSessionId}/builder?externalSessionRail=1&hideHistory=1&hideNewSession=1&dolphin_token={shortLivedToken}
```

After the first request, ai-builder redirects to the same URL without `dolphin_token` and sets `dolphin_code_runtime_{shellSessionId}`. All runtime assets, API calls, event streams, and cookies stay under `/api/code-runtime/{shellSessionId}`.
