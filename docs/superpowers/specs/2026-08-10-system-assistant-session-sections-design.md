# 系统助手双会话区设计

## 目标

在系统助手左侧栏同时提供“系统会话”和“应用会话”，让用户能区分全局系统工作与具体应用工作，并从同一入口快速切换。

## 已确认设计

- “系统会话”展示 `assistant_profile=system_assistant` 的会话，按更新时间倒序排列，不按日期分组。
- “应用会话”展示当前 Code 工作台可访问的真实应用会话，按应用名称分组。
- 两个区域位于同一左侧栏，共用可滚动空间；区域标题可折叠，不增加额外 Tab。
- 点击系统会话仍进入 `/code/system-assistant?session=<id>`。
- 点击应用会话进入原有应用 Code 会话入口，不复制、不转换会话数据。
- 系统会话保留新建、重命名和删除；应用会话沿用原有管理规则。

## 数据边界

- 系统会话继续由 `aiChatApi.listSessions({ mode: 'code', assistant_profile: 'system_assistant' })` 获取。
- 应用会话继续由 `codeRuntimeApi.listRailHistory(...)` 获取。
- 任一数据源失败时只影响对应区域，不能清空另一个区域。

## 非范围

- 不合并系统会话和应用会话的数据模型。
- 不增加“今天 / 昨天”等日期分组。
- 不修改后端 API、会话持久化或权限模型。

## 验收

1. 系统助手左栏同时显示“系统会话”和“应用会话”。
2. 系统会话不出现日期分组，应用会话按应用名称分组。
3. 两类会话都可点击进入正确页面，当前项高亮正确。
4. 一类会话加载失败时，另一类仍可正常显示和使用。
5. 低高度窗口下左栏可以滚动，底部租户和账号区域不被遮挡。
