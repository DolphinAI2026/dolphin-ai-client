# 桌面 Code 本地与远程应用体验设计

**Spec ID**：`2026-07-28-desktop-code-local-remote-application-experience`
**日期**：2026-07-28
**状态**：已确认，进入实现
**工程**：`apaas-builder-ai`

## 1. 目标

桌面 Code 模式以本地开发为默认体验。用户可以快速创建一个本地应用项目，重启客户端后继续看到并打开它；打开过程能够明确显示本地 Runtime 的真实启动阶段，失败时在当前页面恢复，不依赖远程租户或 Code Control Plane。

本地应用与远程应用是两个独立生命周期。未来可以增加“发布到远程”和“拉取到本地”，本轮只保留清晰的数据边界，不展示未实现入口。

## 2. 应用入口与分区

- 桌面 Code 左栏只保留“新建本地应用”和“我的应用”，不同时展示含义重叠的泛化“新建应用”。
- “我的应用”顶部使用 `本地应用 | 远程应用` 分段控件。
- 桌面首次进入默认本地应用，之后记住上次选择。
- 本地与远程列表独立加载、独立空状态、独立错误状态。远程失败不得清空本地列表、退出桌面登录或触发整页跳转。
- Web/远程部署只显示远程应用，不渲染本地入口、分段控件、本地目录或本地 Runtime 状态。

本地列表展示名称、只读应用编码、项目目录和更新时间；远程列表展示名称、编码、所属租户、远程状态和更新时间。点击应用整行直接打开对应工作台，次要操作放入更多菜单。

## 3. 新建本地应用

新建流程使用一个弹窗，不连续显示多个 prompt：

- `应用名称` 必填。
- `应用编码` 根据名称自动生成并预填，创建前可编辑，创建后永久只读。
- `保存位置` 默认使用桌面应用数据目录，文件夹按钮调用系统目录选择器。
- `最终项目目录` 只读展示为 `<保存位置>/<应用编码>`。
- 名称变化时自动更新尚未手动编辑的编码；手动编辑后不再覆盖。
- 保存位置只表示父目录。一个本地应用就是该父目录下的一个独立项目目录。
- 编码、目录冲突和非法字符在字段下就地提示。
- 弹窗操作只保留“取消”和“创建并打开”。

提交后先持久化本地应用 metadata、创建项目目录并注册 workspace，然后立即进入工作台。Git 准备和 Runtime 启动由工作台启动层承接，不让创建弹窗长时间停留。

## 4. 打开与恢复

本地工作台加载层依次显示：

1. 检查本地项目。
2. 启动本地环境。
3. 打开 Code 工作台。

当前阶段显示进行状态和累计耗时，已完成阶段显示完成状态；技术详情默认折叠。已有 Runtime 或缓存 iframe 时直接恢复，不重复初始化。cold start 才执行项目检查、Runtime 启动和 iframe 建立。

固定 30 秒不得直接判定失败。只要后端仍返回启动中，前端继续显示当前阶段；只有后端明确失败或失联达到错误条件时才进入失败状态。失败页面提供“重试”和“返回应用列表”，并按错误类型提供最小恢复动作：workspace 错误允许重新选择保存位置，Runtime manager 错误允许重启本地环境。

所有状态和恢复动作留在应用窗口内，不弹出命令行窗口、不循环刷新、不跳回登录页。应用内切换会话复用当前 Runtime，不重新启动项目。

## 5. 数据与性能边界

- 本地应用 metadata 必须持久化到桌面 sidecar/backend 存储，不能只存在前端内存。
- 本地创建、列表和打开不调用 Code Control Plane。
- 远程应用保持现有线上接口和租户语义，本地 Runtime 不能污染远程请求。
- workspace 所有权和路径合法性在探测 Runtime manager 前完成轻量校验；非法路径必须返回 workspace 错误，不能被 manager 不可用覆盖。
- warm open 跳过 Git/session 重准备；创建操作不提前启动 Runtime。
- 默认运行态数据优先使用桌面数据目录，避免把高频运行文件放在 `/mnt/d` 慢路径。

## 6. Code 输入区目录上下文

- Code 会话在消息输入框底栏左侧展示当前工作区目录，和模型选择器处于同一工具栏。
- 桌面端对本地与远程 Code 工作区都展示该目录上下文，不因当前应用来源隐藏其中一类。
- 展示文本只保留路径最后一级目录，格式为 `本地目录 · <目录名>` 或 `远程目录 · <目录名>`。
- 完整绝对路径仅放在悬停提示中，长路径不得撑宽输入框或挤压发送按钮。
- 本地与远程工作区统一读取工作区接口返回的 `workspace_type` 和 `disk_path`，不得只覆盖 `external` 本地工作区。
- 目录上下文只用于展示，不拼进用户消息，不改变会话工作区绑定，也不触发额外 Runtime 启动。
- 该位置是未来本地/远程工作区切换器的固定入口；当前未实现切换时保持只读，不展示不可用的下拉箭头或伪交互。
- 顶部 Git 工具区不再重复展示目录路径，只保留工作区、分支和远程仓操作。

## 7. 验收标准

- 桌面首次进入显示本地应用；切换远程后可返回且记住选择。
- 新建本地应用只出现一个弹窗，系统目录选择器可用，最终目录规则正确。
- 客户端重启后本地应用仍在列表并可重新打开。
- 远程未登录或不可用时，本地创建、列表和打开仍可用。
- 首次打开显示真实阶段，warm open 明显更快且不重复初始化。
- 打开过程中不出现命令行窗口、登录循环、持续重连或无解释空白页。
- 不再出现 `LOCAL_APPLICATION_WORKSPACE_REQUIRED`、错误覆盖后的 `LOCAL_RUNTIME_MANAGER_UNAVAILABLE` 或固定等待后的伪超时。
- 本地 Code 会话输入框显示 `本地目录 · <最后一级目录>`，远程 Code 会话显示 `远程目录 · <最后一级目录>`。
- 目录较长时输入框布局稳定，悬停可查看完整绝对路径。

## 8. 非目标

- 本轮不实现“发布到远程”或“拉取到本地”。
- 不增加应用详情页、创建向导或第二次确认弹窗。
- 不重做 Code 内层编辑器、会话模型或远程租户管理。
- 不用 mock 替代真实本地 Runtime 和 Windows 桌面验收。
