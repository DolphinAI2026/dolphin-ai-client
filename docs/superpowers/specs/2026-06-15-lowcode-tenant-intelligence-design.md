# 低代码租户智能化接入 AI Builder - 设计文档

- 日期: 2026-06-15
- 状态: 设计已确认, 待拆 plan
- 目标租户样本: `828940713101099009`
- 相关调研: [低代码后台 API 调研清单](../../research-lowcode-admin-api-2026-06-15.md)

## 1. 背景

当前低代码后台已经覆盖租户管理、应用管理、资源配置、自开发管理、权限、日志、异步任务、流程实例、AI 模型与提示词等模块。AI Builder 不应该复制一个后台管理台, 而应该作为客户面对低代码资产时的智能工作台:

- 面向租户: 读取该租户下全部应用, 做组合分析、风险识别、运营建议。
- 面向单应用: 拉取应用完整资源图谱, 做配置诊断、二次开发辅助、运维排障、运营复盘。
- 面向动作: 先给出分析和 diff, 用户确认后再调用低代码后台 API 写回。

关键边界仍然不变: aPaaS 持有租户、应用、权限、发布状态的事实源; AI Builder 持有快照、分析结果、会话、草稿、patch、工作区绑定和交付产物。

## 2. 目标与非目标

### 目标

1. 支持租户级扫描: 获取租户下全部应用, 形成应用资产地图和智能化成熟度视图。
2. 支持单应用深钻: 对一个应用生成资源图谱, 覆盖菜单、模型、表单、流程、事件、权限、自开发包、服务集成、日志和任务。
3. 围绕四类问题形成 AI 能力闭环:
   - 配置: 诊断、生成、调整、差异对比、确认写入。
   - 二次开发: 识别自开发资产, 进入 IDE 修改, 绑定菜单/权限/服务集成, 回填交付包。
   - 运维: 发现流程实例、异步任务、发布、日志、健康指标中的异常。
   - 运营: 输出应用组合分析、AI 改造机会、风险清单和客户成功报告。
4. 接入低代码后台 API, 但默认只读; 所有写操作必须走确认门。

### 非目标

- 不做新的低代码后台替代品。
- 不在 AI Builder 本地复制 aPaaS 的完整配置数据库。
- 不把每个租户应用初始化成 AI Builder 的本地主应用; 只在需要分析或行动时建立影子记录和快照。
- P0 不做批量自动修改、自动发布、自动下线。

## 3. 产品形态

### 3.1 租户智能驾驶舱

入口: AI Builder 的租户/应用管理视图中新增「租户智能分析」。

核心内容:

| 模块 | 展示内容 | AI 能力 |
| --- | --- | --- |
| 应用组合 | 应用数量、上线状态、最近变更、业务域分布 | 识别重点应用、沉睡应用、重复建设 |
| 资源规模 | 模型、表单、流程、事件、自开发包、服务集成数量 | 判断复杂度和维护成本 |
| 风险雷达 | 权限过宽、流程异常、任务失败、日志异常、未绑定自开发资产 | 生成风险解释和修复建议 |
| 智能化机会 | 可用 AI 建模、AI 功能创建、Prompt 治理、流程自动化机会 | 输出改造优先级 |
| 运营报告 | 面向客户/CSM 的周报、月报、体检报告 | 一键生成报告草稿 |

租户总览只做跨应用聚合, 不直接写配置。

### 3.2 单应用资源图谱

入口: 应用卡片、应用详情、聊天上下文中都可以进入「应用智能体检」。

资源图谱节点:

- 应用: 基本信息、状态、版本、环境、管理员、密钥状态。
- 菜单: 分组、页面、表单菜单、自开发菜单、AI 功能创建入口。
- 数据: 数据模型、模型字段、业务对象、数据字典、数据源。
- 页面: 表单配置、详情页、列表页、查询条件、按钮、权限样式。
- 逻辑: 流程、流程版本、业务事件、服务集成、公式规则、业务规则。
- 权限: 访问权限、功能权限、数据权限、角色、成员、黑名单。
- 二开: 自开发包、自开发权限、菜单绑定、工作区绑定、交付包版本。
- 运维: 应用日志、租户日志、异步任务、流程实例、健康指标。

每个节点都保留 `source_endpoint`、`source_id`、`fetched_at`、`app_id`、`tenant_id`, 便于追溯和刷新。

### 3.3 AI 行动面板

单应用页右侧提供行动面板, 不是一个泛泛聊天框。默认任务类型:

| 任务类型 | 输入 | 输出 |
| --- | --- | --- |
| 配置体检 | 当前应用资源图谱 | 问题清单、影响范围、修复建议 |
| 配置变更 | 用户意图 + 当前配置 | 变更计划、diff、确认写入动作 |
| 二开修改 | 自开发资产 + 需求 | IDE 工作区、代码变更、打包/上传建议 |
| 运维诊断 | 日志、任务、流程实例 | 根因候选、处理步骤、可执行动作 |
| 运营分析 | 租户/应用组合数据 | 成熟度评分、机会点、报告草稿 |

## 4. 四类问题的能力映射

| 问题 | 需要接入的数据 | AI Builder 能做什么 | 写回边界 |
| --- | --- | --- | --- |
| 配置 | 应用、菜单、模型、业务对象、表单、列表页、流程、事件、权限、字典、数据源 | 生成配置建议, 检查缺字段/缺查询/权限遗漏, 输出 diff | 用户确认后调用低代码配置 API |
| 二次开发 | 自开发包、自开发权限、菜单绑定、服务集成、工作区、DevAsset | 找到资产归属, 打开 IDE 修改, 生成打包说明, 检查权限和菜单接入 | 上传/更新自开发包必须确认 |
| 运维 | 操作日志、应用日志、流程实例、异常流程、异步任务、发布记录、健康指标 | 聚合失败、定位最近变更、解释异常链路、生成处理步骤 | 重试任务、流程转办、发布类动作必须确认 |
| 运营 | 应用清单、上线状态、资源规模、变更频率、风险结果、AI 配置 | 输出应用组合视图、成熟度、AI 改造机会、客户成功报告 | P0 不写回, 只产出报告 |

## 5. 技术设计

### 5.1 低代码后台连接器

新增连接器建议命名为 `LowCodeAdminConnector` 或 `APaaSAdminClient`。

职责:

- 管理 base URL、tenant id、app id、环境和鉴权上下文。
- 提供 endpoint registry, 按领域暴露只读/写入能力。
- 统一请求日志、错误分类、重试、限流、脱敏。
- 将低代码原始响应 normalize 成 AI Builder 内部图谱对象。
- 记录 API provenance: endpoint、method、params hash、fetched_at、version。

连接器不保存长期 token, 不打印 token/cookie/header 密钥。

### 5.2 快照与图谱

建议新增内部概念, 先不一定都落表:

| 对象 | 含义 |
| --- | --- |
| `TenantSnapshot` | 一次租户扫描结果, 包含应用清单、聚合指标、扫描时间 |
| `AppInventoryItem` | 应用列表行的标准化表示 |
| `AppResourceGraph` | 单应用资源图谱, 包含节点、边、发现的问题 |
| `ResourceNode` | 模型/表单/流程/事件/权限/自开发包等资源节点 |
| `ResourceEdge` | 菜单指向表单、表单使用模型、流程引用表单、自开发包绑定菜单等关系 |
| `ConfigHealthFinding` | 配置问题、风险、建议 |
| `ActionProposal` | AI 建议执行的写入动作, 必须可 diff、可确认、可回滚说明 |

快照是 AI Builder 的观察态, 不是事实源。刷新策略:

- 用户手动刷新: 立即重新拉取。
- 自动刷新: P0 可先不做; P1 根据 TTL 刷新。
- 写入后刷新: 成功写入配置后只刷新受影响资源域。

### 5.3 工具权限分级

| 级别 | 说明 | 示例 |
| --- | --- | --- |
| L0 只读 | 查询、扫描、生成报告 | 应用列表、资源详情、日志查询 |
| L1 低风险写 | 非破坏性保存, 可明确 diff | 更新列表页查询条件、补充字段别名 |
| L2 高风险写 | 影响访问、流程、集成、运行态 | 权限调整、流程启停、事件保存、自开发包更新 |
| L3 发布/删除 | 影响生产可用性或不可逆 | 发布、下线、删除应用/资源、终止流程 |

P0 只开放 L0。P1 开 L1/L2, 但必须确认。L3 始终需要二次确认, 并展示影响范围。

### 5.4 与现有 AI Builder 的关系

- AI Builder 是唯一可见工作台; 自开发资产点击后直接进入 IDE, 不恢复独立 AI Coding 入口。
- 已有配置助手统一到 unified agent 的方向继续保留; 新连接器作为 unified 工具域之一。
- `app_id` 是 AI Builder 本地应用主键, `apaas_app_id` 是低代码平台应用 ID, 两者不可混用。
- 自开发资产必须支持已绑定/未绑定两种状态; 单应用图谱只能展示与该应用有明确关系的资产, 租户图谱可以展示孤立资产并提示绑定风险。

## 6. API 接入优先级

### P0: 只读分析闭环

1. 租户应用清单与状态: 应用数量、状态、最近安装/发布信息。
2. 单应用资源图谱: 菜单、模型、业务对象、表单、列表页、流程、事件、权限、自开发、服务集成。
3. 运维信号: 操作日志、异步任务、异常流程实例、健康信息。
4. AI 分析输出: 配置体检、二开绑定检查、运维诊断、运营报告草稿。

### P1: 确认写入闭环

1. 配置 diff 写回: 表单、列表页、菜单、事件、权限。
2. 自开发闭环: 工作区修改、打包、上传、菜单/权限绑定。
3. 运维动作: 任务重试、流程转办/授权、局部修复动作。

### P2: 租户运营智能化

1. 多应用趋势: 复杂度、变更频率、风险趋势。
2. AI 成熟度: 哪些应用适合接 AI 功能、Prompt、流程自动化。
3. 客户成功报告: 面向客户的定期体检和改造路线图。

## 7. 前端信息架构

建议新增或改造这些页面/区域:

| 页面/区域 | 说明 |
| --- | --- |
| 租户智能分析页 | 租户级应用组合、风险、机会和报告入口 |
| 应用详情智能页签 | 单应用图谱、体检结果、资源追溯 |
| AI 行动面板 | 固定在图谱/应用详情右侧, 支持任务化对话 |
| 运维诊断页 | 聚合日志、任务、流程实例、发布状态 |
| 报告中心 | 保存租户体检、应用体检、运营报告草稿 |

交互原则:

- 用户先看结果, 再决定是否让 AI 展开解释。
- 每个建议必须能回到具体资源节点。
- 每个写入建议必须有 diff。
- 每个高风险动作必须显示影响范围。

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 接口多且 payload 差异大 | endpoint registry + normalizer 分域接入, 先只读 |
| 鉴权头/部署前缀因环境变化 | connector 按环境配置 base URL 和 header 策略 |
| AI 误写生产配置 | 默认只读, 写入必须 diff + 用户确认 |
| 权限扩大或越权分析 | 所有查询绑定 tenant id, 所有应用查询绑定 app id, 工具层二次校验 |
| 自开发资产与应用关系不完整 | 租户图谱展示孤立资产, 单应用图谱只展示明确绑定资产 |
| 日志中包含敏感信息 | 存储前脱敏, prompt 注入前裁剪 |
| 前端变成后台复制品 | 页面以洞察、图谱、行动为主, 后台表格只作为 drill-down |

## 9. 待补抓与开放项

- 「提示词管理」CRUD endpoint 未在静态包中明确定位, 需要 DevTools 网络面板继续补抓。
- 模型与提供商管理目前只看到 AI 集成配置查询/保存, 仍需确认 provider/model 详情 API。
- 应用列表、表单详情、权限详情的返回 schema 需要用真实 XHR 样本固化。
- 哪些写接口可以复用现有 MCP/工具, 哪些需要新增 connector action, 需要 plan 阶段逐个对表。
- 需要确定快照是否落库, 以及 raw response 的保留时间和脱敏策略。
