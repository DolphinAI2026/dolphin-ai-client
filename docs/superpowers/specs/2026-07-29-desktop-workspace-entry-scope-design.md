# 桌面端工作台入口范围设计

**Spec ID**：`2026-07-29-desktop-workspace-entry-scope`
**日期**：2026-07-29
**状态**：已确认
**工程**：`apaas-builder-ai`
**目标端**：桌面端

## 1. 目标

允许用户决定桌面端展示哪些一级工作台入口，并统一顶部名称：

- `Builder` 统一显示为 `aPaaS`。
- `Code` 统一显示为 `AI平台`。
- 可选范围为“仅 aPaaS”“仅 AI平台”“两者都有”。

该设置只控制桌面端一级工作台入口及对应路由，不改变登录服务、租户、Runtime 或应用
数据。

## 2. 配置合同

在 `<根目录>/.appdata/desktop-config.json` 增加 `workspace_entry_scope`：

```text
apaas | ai_platform | both
```

- 新安装首次初始化不预选，用户必须明确选择后才能保存。
- 旧配置缺少该字段时，仅为升级兼容读取为 `both`，不要求重新初始化。
- 配置由 Tauri/Rust 持久化，前端缓存不得成为事实源。

## 3. 交互

首次初始化的“本地存储”步骤增加“工作台入口”分段选择，三个选项均无初始选中态。
未选择时禁用“保存并进入登录”。

“桌面设置”增加独立的“工作台入口”区域。保存后立即更新顶部入口，不退出当前账号，
不重启 sidecar 或 Runtime。登录服务继续使用原有“保存并重新登录”动作，两类设置不共用
保存按钮。

顶部入口规则：

- `apaas`：只显示 `aPaaS`。
- `ai_platform`：只显示 `AI平台`。
- `both`：依次显示 `aPaaS`、`AI平台`。

单入口时保留一个可见 Tab，明确当前产品入口。修改设置后，如果当前路由属于刚被隐藏
的入口，立即跳转到所选入口首页。

## 4. 路由与兼容

桌面路由守卫读取原生配置并阻止进入被隐藏的一级工作台：

- `apaas` 下访问 `/code` 或 `/code/*`，跳转到 aPaaS 首页。
- `ai_platform` 下访问其他业务页，跳转到 `/code/apps`。
- 初始化、登录、桌面设置和错误恢复路由不受入口范围阻塞。
- Web 端继续显示原有 `Builder / Code`，不消费桌面配置。

## 5. 实现边界

- Rust 配置类型负责校验、旧配置兼容和原子持久化。
- 前端桌面配置门面负责类型映射和 Tauri command 调用。
- 初始化向导和桌面设置只消费共享配置类型。
- `mode.ts` 提供按范围筛选入口的纯函数，`RailSidebar.vue` 不自行复制枚举规则。
- 只修改既有 Rust 内联测试及既有前端测试文件，不新增分散测试文件。

## 6. 验收标准

1. 新安装未选择工作台入口时不能完成初始化。
2. 旧配置升级后仍可启动，并显示两个入口。
3. 三种范围分别产生正确的顶部 Tab。
4. 保存桌面工作台设置后立即生效，且不触发退出登录或本地服务重启。
5. 被隐藏入口的直接路由会跳转到可用入口。
6. Windows 安装包仍为单一 EXE，并同时包含中文 NSIS 与 Windows SQLite 路径修复。
