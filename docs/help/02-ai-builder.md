# AI 搭建（应用编辑页）

**入口**：`/apps` 应用列表 → 点任意应用 → 进入编辑页（`/chat?app_id=xxx`）。

**说明**：左侧导航没有"AI 搭建"独立菜单。直接访问 `/chat`（不带 app_id）会自动重定向到 `/apps`，因为编辑页必须有应用上下文才有意义。

## 页面结构（双栏布局）

进入应用后页面分两栏：

- **左栏：应用内 AI 助手**（应用调整助手 inline 嵌入）
- **右栏：SPEC 实时视图**（基础配置 / 模型 / 表单 / 业务流程，**只读**）

页面顶部有一个紫色提示条：「📌 当前在编辑 {应用名} #{app_id}」+「复制上下文」按钮。

## 左栏：AI 应用调整助手

应用内 AI 助手有一组 MCP 工具可以直接操作当前应用：

| 工具 | 用途 |
|---|---|
| `list_my_applications` | 列出我能访问的所有应用（用户问"我有哪些应用"时调）|
| `get_application` | 查看当前应用完整 SPEC（含字段、表单、权限）|
| `parse_design_doc` | 解析一份 markdown 设计文档（不创建应用）|
| `generate_app_from_doc` | 根据完整 markdown 一步创建新应用 |
| `update_app_from_doc` | 上传新版设计文档，自动 diff 出变更计划 |
| `get_change_plan` | 查看变更计划详情（哪些字段加 / 改 / 删）|
| `execute_change_plan` | 执行变更计划，落到底层应用 |
| `publish_application` | 把应用上线到 aPaaS 平台 |

**典型对话流**：

> 用户：销售订单表单加一个 remark 字段（多行输入）
> 助手：（调 get_application 拿当前 SPEC）→（生成新版 markdown）→（调 update_app_from_doc 拿到 plan_id）→（直接调 execute_change_plan 执行）→ 已完成。销售订单表单新增 remark 字段（text 类型，多行输入）。

整个流程**一气呵成**，不会反复确认"是否提交预览"。**例外**：删字段、删模型、改主键等破坏性操作前会停下确认。

## 右栏：SPEC 实时视图

显示当前应用的完整 SPEC（结构化设计文档反向渲染），包含 6 章节：

1. **应用信息**（应用名 / 编码）
2. **角色列表**
3. **数据字典**（枚举类型）
4. **数据模型**（表 + 字段）
5. **表单定义**（字段组件 / 必填 / 隐藏 / 只读 / 列表展示等）
6. **业务流程**（如有）
7. **权限定义**（角色 × 表单 × 操作）

**自动联动**：左栏 AI 助手改完应用后，右栏在 5 秒内自动刷新，弹 toast「AI 助手已更新应用配置」。无需手动刷新页面。

右栏所有内容**只读**——所有编辑都通过左栏 AI 对话完成。

## 应用上下文自动注入

进入编辑页时，前端会自动告诉 AI 助手「用户当前在编辑应用 #X（名字）」。后续工具调用不需要用户反复传 app_id。

如果对话过程中 agent 没识别到当前应用（罕见），可以点紫色提示条上的「复制上下文」按钮，把"当前编辑应用 #X（Y）"复制到剪贴板，发消息时粘贴一下。

## 创建应用的两条路径

**A. 从首页 Builder 入口拖 .md 文件**（首页 `/`）：
- 拖一个 `.md` 设计文档进来
- 自动跳到 `/chat?from=upload`，AI 解析创建新应用，URL 自动加上 `?app_id=新ID`
- 文档必须符合 6 章节标准模板（应用信息 / 角色 / 数据字典 / 数据模型 / 表单 / 权限）

**B. 进入已有应用直接对话**：
- 在 `/apps` 列表点应用 → 进编辑页
- 直接对左栏 AI 说「加 xxx 字段」「改 xxx 名字」即可

## 部署到 aPaaS 平台

当应用从草稿变成「需要部署到底层 aPaaS 平台」时：

- 直接对 AI 说「发布上线」/「部署到平台」 → agent 调 `publish_application` 工具

注意：编辑页**没有**单独的"部署到预览"按钮（已删除，统一让 AI 助手调工具完成）。

## 文档模板规范（重要）

`update_app_from_doc` / `parse_design_doc` 工具上传的 markdown 必须严格符合标准 6 章节模板：

```
## 一、应用信息
| 应用名称 | 应用编码 |
| ... | ... |

## 二、角色列表
| 角色编码 | 角色名称 |
...

## 三、数据字典
...

## 四、数据模型
### 4.1 模型定义
| 模型编码 | 模型名称 |
...

### 4.2 模型字段
| 模型编码 | 字段编码 | 字段名称 | 字段类型 | 长度/精度 |
...

## 五、表单定义
...

## 六、流程配置（可选）
...

## 七、权限定义
| 表单名称 | 角色编码 | 可暂存 | 可新增 | 可导入 | 可查看 | 可编辑 | 可删除 | 可导出 | 数据范围 |
...
```

ai-builder 后端用纯代码（无 LLM 兜底）严格解析这个模板。如果 AI 助手写的 md 章节标题或表格列错乱，后端会自动用 LLM 把它规范化后重试一次。

## 跟其它模块的关系

- 想从需求 / 资料聊出标准 .md 设计文档？→ AI 对话（`/ai-chat`）
- 想给 aPaaS 平台加自开发组件？→ AI 编码（`/coding`）
