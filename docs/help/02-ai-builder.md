# AI 搭建 (`/chat`)

**把设计文档喂给 AI → 生成 SPEC → 部署到平台。** 整个 aPaaS 应用的搭建主流程。

## 4 阶段流水线

进入应用后顶部有 phase strip：

1. **理解需求**：上传 .md / 描述业务，AI 解析成结构化 SPEC（角色 / 数据字典 / 数据模型 / 表单 / 权限 / 业务流程）
2. **SPEC 设计**：在右侧可视化看 SPEC，可补充 / 修改 / 重新让 AI 细化
3. **配置生成**：把 SPEC 转成 aPaaS 平台可识别的配置（模型 + 表单 + 流程）
4. **部署**：把配置推送到平台环境，应用就能在平台预览运行

## 关键能力

- **侧边栏**：左侧列出所有应用（点击切换），「+ 新建应用」直接进入新应用流
- **SPEC tabs**：右侧面板按基础配置 / 模型 / 表单 / 业务流程切换查看
- **直接上传文档**：在欢迎态可以拖一个 `.md` 进来，AI 自动解析成 SPEC（解析进度卡可见 ✅角色 / 字典 / 模型 / 表单 / 权限 / 文档）
- **变更管理**：已部署应用想改 SPEC？编辑后会生成新 draft，到 DevOps 走"提案 → 审批 → Apply"
- **预览 / 部署**：顶部右侧"部署到预览"按钮一键发布

## 数据流

```
设计文档.md ─┐
            ├─> AI 解析 ─> SPEC (Pydantic 文档) ─> 平台配置 ─> aPaaS 应用
对话需求 ───┘                  │
                              └─> draft → DevOps 提案 → Apply → canonical
```

## 入口路径

- 从 `/apps` 点应用卡片 → 自动跳 `/chat?app_id=xxx`
- 已生成的应用进 `?tab=spec&workspace=update` 直接打开 SPEC 编辑工作台
- 从 AI 对话点「→ Builder」过来，会带上 `.md` 自动开搭

## 命名

- **应用 (Application)**：本地 builder 应用 + 平台 remote 应用合并视图
- **canonical SPEC**：上一次 apply 成功的 SPEC，是当前生效版本
- **draft SPEC**：你正在改的草稿；改完后到 DevOps promote 成 proposal

## 与 AI 对话的关系

AI 对话产出的是**标准 .md 文档**；AI 搭建吃这个 .md 直接生成 SPEC。两个模块串起来就是"需求 → 文档 → 应用"的完整链路。可以跳过 AI 对话直接在 AI 搭建上传 .md，但用 AI 对话整理后的 .md 解析成功率更高。
