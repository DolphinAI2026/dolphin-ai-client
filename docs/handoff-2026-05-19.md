## B. 功能缺陷 / 半成品

### B1. ConfigAssistantPanel (`/chat?app_id=N` 右侧助手)

| Stub | 现状 | 应该做的 |
|---|---|---|
| `applyChangePlan` | `ElMessage.info('Plan D+1 待接入 incremental_update apply')` | 接 `app/services/incremental_update.apply` |
| `previewDiff` | `ElMessage.info('Diff preview 待 Plan D+1 接入')` | 用 `incremental_update.previewUpdate` 渲 diff |
| 消息持久化 | 内存 ref，刷新就丢 | 后端加 `config_chat_messages` 表 / 复用 conversations |
| SSE 流式 | 单轮 await `chat_completion`，长 reply 长等 | 改 SSE，类似 ai_chat |
| tool_trace 展开 | 只显示 `✓ list_apaas_app_models` chip | 点开看 args/result JSON，方便 debug |

### B2. AppChatPanel (`/chat?app_id=N` MD 助手)

- "应用最新 md 到 Builder" 按钮：post-deploy 状态下是不是变成"应用增量更新"？现在两种状态走同一个 handler，可能撞 — 需验证
- 输入框 placeholder 描述过窄
- 长对话 history 没分页，全加载

### B3. /coding (睿鲸 AI Coding)

- 导入 zip：30MB 上限；自开发包通常这么小够用，但 vibe 用例可能大；后端 `import_zip_to_workspace` 还有 vibe 路径 (`upload_external_zip_to_apaas`) 没暴露 UI
- "📦 产物" toggle 已加，但产物面板的"接入说明"还是固定 4 步，没根据 project_type 分支 (form-component vs form-page vs backend-api 流程不同)
- coding chat 撞 `conversation_id NULL` 已修；其他类似 endpoint (`vibe_coding_chat` / `online_coding`) 可能同 pattern bug 待审

### B4. 部署 (DeployConfirmModal + 后端 deploy-from-artifact)

- 砍了 env picker 后默认走 'test'；如果 tenant 有多个环境怎么办？目前看用户场景是"每租户 1 个环境"所以 OK，但 SaaS 多租户场景待考虑
- 部署失败重试只到 confirm phase，没保留具体 step 失败上下文
- 没"取消正在进行的部署" — 一旦 deployOpen，只能等

### B5. /apps 同步

- 缺：定时全量回填（譬如启动 hook 跑一次）；现在只在 list 接口请求时回填，list 不请求就不同步

### B6. 行业知识库 / 组件市场（已从 nav 隐藏）

  - 导入企业包 .zip 按钮没接后端解析逻辑
  - 派生新包 → 没 UI 流程
  - 组件 publish flow 后端有 endpoint，前端 "我的发布 / 升级 / 卸载" UI 不完整
  - "已被 1 个客户 / 应用采用" 数字是死的，没真实统计
