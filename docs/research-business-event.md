## 1. 概念架构

### 1.1 三件套定义

业务事件 = 一套**可视化逻辑编排语言**，业务人员通过点击配置即可完成业务流程编排（"火车"比喻：节点=车厢）。

完整业务事件 = **触发埋点 + 若干执行节点** 串联，加上贯穿全局的**标准上下文**。

```
[触发节点 触发器] ──→ [执行节点1] ──→ [执行节点2] ──→ ... ──→ [输出]
                          ↑ 全程可读 标准上下文 全局变量
                          ↑ 每个执行节点都有"数据来源节点"指向前序某节点
```

### 1.2 前/后端埋点分类（关键架构决策）

| 维度 | 前端埋点 | 后端埋点 |
|---|---|---|
| 触发方式 | 操作前 / 操作成功后 / 按钮 / 字段值改变 / 子表操作 | 操作后 / 定时 / 外部 / 流程触发 / 节点操作后 |
| 实现机制 | 浏览器请求 `trigger` → 逐节点 `NormalNode` → `Complete` | 后端监听数据库或调度服务，浏览器无任何接口请求 |
| 强依赖 | 网络环境 / 浏览器状态（不稳定） | 后端服务稳定运行 |
| 可触发执行节点 | **全部** 18 个节点（含前端的页面交互类） | **仅后端节点**（页面交互类全部不可用）|

含义：**前端埋点 业务事件 = 前端弹窗+赋值+刷新+查询+新增+...; 后端埋点 业务事件 = 数据库流转 + 集成 + 自定义代码，不允许出现 UI 动作**。

### 1.3 启用前置

1. 平台管理→插件管理：开启「业务事件」插件
2. 后台管理→插件管理：同样开启
3. 插件状态变化后**应用内业务事件需手动重新开启**（导入应用包时常见坑）
4. 定时触发额外要求：开启「定时服务」插件 + powerjob 服务正常 + 应用已上线

## 2. 触发器全集（7 种）

> 关键铁律：**业务事件创建后触发类型不可改**，只能删除重配。

| # | 触发器 | 入口 | 埋点类型 | 同步/异步 | 关键入参 | 适用场景 |
|---|---|---|---|---|---|---|
| 1 | **表单操作触发** | 应用业务事件中心 / 表单业务事件中心 | 前/后端混合 | 操作前=同步、操作后=异步可切、成功后=同步 | 触发表单 / 触发类型(提交/保存/暂存/修改/删除/导入...) / 触发方式(前/中/后) / 数据触发范围 / 字段变更校验规则 / 是否使用前后数据 | 提交后自动生成关联单据 / 导入后批量分发 |
| 2 | **子表操作触发** | 表单设计→子表组件 | 前端 | 同步不可改 | 触发表单(=主表，不可改) / 触发类型(新建/删除) / 触发方式(前/后) / 数据触发范围 | 子表新增前弹窗 / 子表删除后联动废弃 |
| 3 | **按钮触发** | 表单按钮 / 子表按钮 / 列表按钮 / 批量操作按钮 | 前端 | 同步不可改 | 节点名称 / 数据触发范围（其余置灰）; 列表按钮**只起触发作用不传数据**，需配查询节点 | 自定义按钮触发整段流程 / 批量勾选数据再处理 |
| 4 | **字段值改变触发** | 表单字段（一字段=一业务事件，1:1）| 前端 | 同步不可改 | 节点名称 / 数据触发范围（其余置灰）| 选商机字段后查询 + 自动赋值客户信息 |
| 5 | **定时触发** | 应用业务事件中心 | 后端 | 默认异步可切 | 触发方式(仅触发一次 / 重复触发 / 自定义 Cron) / 开始时间 / 结束时间 / 周期 / Cron 表达式 | 定时清理 / 日报推送 |
| 6 | **审批流程触发** | 应用业务事件中心 / 流程设计→事件节点 | 前/后端混合 | 进节点前/操作前/成功后=同步；节点结束后/操作后=异步可切 | 触发流程 / 触发类型(流程触发 vs 节点触发) / 触发节点 / 触发方式(进入前/结束后/操作前/操作后/成功后) | 审批通过后生成证明 / 节点结束后通知 |
| 7 | **外部触发** | 应用业务事件中心 | 后端 | 默认同步可切 | 系统生成的触发 URL（POST） / 输入参数配置(JSON 自定义 或 模拟请求) / 可选 token 验证（`xdaptoken` header） / **必须配输出节点**（最后一个节点定义 response 结构）| 外部 CRM 推订单进 aPaaS / 外部系统状态变更通知 |

**6 子类型继承父类的标准上下文**（见 3.3）。

## 3. 执行节点全集（17/18 种，4 大类 + 引用）

### 3.1 总览表

| 类别 | 节点 | 前/后端 | 数据来源节点必填 | 核心能力 |
|---|---|---|---|---|
| **页面交互类（5）** | 更新页面 | 前端 | 否 | 刷新页面/列表/弹窗、关闭弹窗、toast |
| | 弹窗事件 | 前端 | 否（二次确认）/ 是（含字段引用） | 二次确认 / 收集信息 / 自定义 JS+CSS 弹窗 |
| | 字段赋值 | 前端 | 是 | 给当前打开的编辑/审批表单字段赋值（不落库，需 submit） |
| | 数据校验 | 前端 | 是 | 校验数据是否通过，可终止事件并 toast |
| | 调用节点 | 前端 | 是 | 唤起其他表单的新增/详情/编辑弹窗 |
| **数据操作类（5）** | 查询节点 | 后端 | 是 | 按规则查询业务对象，可控查询为空时是否继续，可排序+限条数 |
| | 新增数据 | 后端 | 是 | 按主对象数 OR 子表行数 新增；状态可选 提交/暂存/完成；可触发消息提醒 |
| | 更新数据 | 后端 | 是 | 按关联规则更新；可配「无可更新数据时自动新增」；含子表 5 种更新规则 |
| | 删除数据 | 后端 | 是 | 物理删除（不可恢复）；可仅删主或仅删子表行 |
| | 提交数据 | 后端 | 是 | 草稿 → 正式（触发审批流）；可同步/异步切（提交大量数据建议异步） |
| **逻辑控制类（5）** | 分支节点 | 后端 | 是 | 多分支+优先级（0-1000）+ 默认分支；**多条数据按第一条判断流向**（要逐条需配合循环节点）|
| | 循环节点 | 后端 | 是 | 同步/异步循环；可配跳出规则、单次异常处理、最大次数(1-10000)、间隔；**不可嵌套循环、不可含页面动作** |
| | 数据校验 | 前端 | 是 | （归类页面交互，但也属逻辑控制）|
| | 运算节点 | 后端 | 是 | 三种运算：汇总成一条 / 逐条运算 / 按维度生成多条；支持公式规则 |
| | 整合节点 | 后端 | 是 | 虚拟拼表（数据库 view）；单条/多条输出；多条用关联规则做内连接 |
| **集成扩展类（4+1）** | 调用节点 | 前端 | 是 | （也归页面交互）|
| | 外部节点 | 后端 | 否 | 调 RESTful API；接口来源=自定义(GET/POST/完整数据) 或 服务集成；可配返回异常处理 |
| | 消息节点 | 后端 | 是 | 提醒对象（指定人/角色/参数化角色/数据来源人员/邮箱）× 提醒方式（系统/邮件/企微/飞书/钉钉/自定义消息）|
| | 引用节点 | 后端 | 是 | 调用「标准工作流」实现业务逻辑复用；引用方式=仅触发 OR 等待执行完成 |
| | 自定义节点 | 前/后端 | 是 | 自开发代码（前端=JS/Python3/Python2/Groovy；后端=Python3/Python2/Groovy）|
| **辅助节点** | 标准工作流 | — | — | 输入节点 + 执行节点 + 输出节点；自身不可含页面动作 + 不可嵌套引用 |
| | 输出节点 | — | — | 外部触发专用，配置 response 结构 |

文档自述「18 种」实际去重后 17 个独立节点（调用节点同时归 页面动作 和 集成扩展，文档列两次）。

### 3.2 数据来源节点 通用规则

几乎所有执行节点都有「数据来源节点」入参，统一规则：

- **支持**：所有触发节点、新增、更新、删除、查询、整合、提交、引用、外部、运算、自定义节点
- **不支持**：分支节点（只导流不输出）、消息节点（不输出）、循环节点（外部不可选）、循环和分支**内部**的所有节点
- **循环内 vs 循环外**：循环内的节点数据来源可选所属循环节点；循环外的节点无法跨进任何循环

### 3.3 关键节点深挖

#### 3.3.1 弹窗事件（3 种弹窗）
- **二次确认弹窗**：标题 + 提示文字 + 确认/取消按钮文字 + 取消后动作(事件终止/继续)
- **信息收集弹窗**：在二确基础上加「收集字段配置」（单/多行/数字/日期/人员/部门/下拉/附件/地区/数据选择 等 12 种字段）+ 一列/两列排列；出参 = 收集字段值
- **自定义弹窗**：自定义 JS 模板 + 自定义 CSS + 返回 Response 示例（JSON 解析成出参参数列表）

#### 3.3.2 字段赋值（5 种子表赋值规则）
| 规则 | 行为 |
|---|---|
| 替换赋值 | 删原表所有行，只保留数据来源行，未配置字段置空 |
| 全量赋值 | 删原行，优先保留来源数据，未配置字段用原值 |
| 部分赋值 | 保留原行，从第一行起按来源覆盖 |
| 增量赋值 | 保留原行，新建行追加来源数据 |
| 批量赋值 | 用来源第一个值批量同步到原子表全部行 |

更新节点子表赋值同上但**没有「部分赋值」**（共 4 种）。

#### 3.3.3 运算节点
- 汇总统计成一条：自定义字段名 + 字段 + 统计方法（全部计数/非空计数/去重计数/总和/平均/最大/最小）
- 逐条运算：每行表单字段 = 数据来源字段 OR 公式规则结果
- 按维度生成多条：先按维度字段分类，每类内做汇总

#### 3.3.4 外部节点（核心：API 集成）
- **接口来源**：自定义 URL OR 选择服务集成（在「服务集成」模块预先维护的 Rest 接口）
- 请求类型：完整数据 / 自定义 GET / 自定义 POST
- Body 格式（POST 专用）：none / form-data / raw(application/json)
- 参数来源：数据来源节点 / 自定义 / 公式规则 / 空值 / 环境参数(User-Agent) / 系统字段(当前用户 Token / 用户 ID / 租户 ID / DocumentId) / 全局信息
- 返回异常：事件终止 OR 继续；可配返回异常 toast / 对话框

#### 3.3.5 引用节点 + 标准工作流
- 标准工作流 = 「输入节点 + 执行节点(不可含页面动作 / 不可嵌套引用) + 输出节点」三段式
- 输入节点支持参数格式：单据号 / 文本 / 长文本 / 数字 / 金额 / 日期时间 / 人员单/多选 / 部门单/多选 / 地区地址 / 主子关系
- 引用方式：「仅触发」（不等结果） vs 「等待执行完成」（取输出）
- 输出节点参数类型：数据来源 / 自定义 / 公式规则 / 空值 / 环境参数

#### 3.3.6 自定义节点（最大开放面）
- 前端可选语言：JavaScript / Python3 / Python2 / Groovy
- 后端可选语言：Python3 / Python2 / Groovy
- 平台提供通用方法 + 自开发包（详见平台开放文档）
- 返回 Response 示例必须和代码实际输出一致

## 4. 通用逻辑深挖（5 件）

### 4.1 数据关联规则（业务事件的"SQL JOIN"）

**用途**：调用节点 / 更新数据 / 整合节点 / 提交数据 的关联规则；删除数据的删除规则；查询节点的查询规则。

**结构**：`左侧业务字段 + 判断条件 + 右侧关联字段(来源字段/自定义/公式/全局信息)`

**判断条件按字段类型**：
| 字段类型 | 可用条件 |
|---|---|
| 文本（单/多行/手机/邮箱/证件号/超链接/单据号/地区/他表/定位/附件 等）| 是/不是 / 包含/不包含 / 存在于/不存在于 / 开头为/结尾为 / 为空/不为空 |
| 数字 | =/≠/>/</≥/≤ / 在范围内/不在范围内 / 为空/不为空 |
| 选项类（人员/部门/单/多选/下拉/数据选择）| 是/不是 / 包含/不包含 / 存在于/不存在于 / 为空/不为空（**支持按齿轮切「按名称」or「按 ID/编码」匹配**）|
| 附件上传 | 仅为空/不为空 |
| 开关 | 是 / 存在于/不存在于 |

**多条件组合**：组内 = 且；组间 = 或。

**坑**：人员/部门 vs 多选字段 字段类型转换矩阵非常复杂（文档第 1 页 2.3.3.x 节占据约 200 行规则）；空字符串 `""` 查询时算"有值"，校验时算"空"。

### 4.2 数据过滤条件（触发节点专用）

**用途**：只有所有触发节点的「数据触发范围」配置，**前置过滤** — 触发动作发生 + 数据符合条件 ⇒ 才执行业务事件。

**结构**：与关联规则几乎一样，三元组 `表单字段 + 判断条件 + 校验值`，组内且、组间或。

**与关联规则的区别**：关联规则是节点内**找数据匹配**（多对多 JOIN），过滤条件是触发时**筛入口数据**（单条 WHERE）。

### 4.3 标准上下文（"全局变量"）

业务事件全程可读的环境信息，所有节点直接获取，强化对触发场景的感知。

**通用信息**（所有触发都有）：当前业务事件名称 / 触发时间 / 触发类型 / 触发方式 / 当前应用 id / 当前租户 id

**触发类型独有上下文**：
| 触发类型 | 通用 | 表单信息 | 流程信息 | 定时任务信息 |
|---|---|---|---|---|
| 表单操作触发 | ✓ | ✓（Form ID, Menu ID, 业务对象名, 业务对象 ID）| ✗ | ✗ |
| 按钮触发 | ✓ | ✓ + 按钮名/类型/Code | ✗ | ✗ |
| 字段值改变触发 | ✓ | ✓ + 触发字段名/ID | ✗ | ✗ |
| 子表操作触发 | ✓ | ✓ + 子表名/ID/业务对象名/ID | ✗ | ✗ |
| 数据导入触发 | ✓ | ✓ + 数据导入模板名 | ✗ | ✗ |
| 流程触发 | ✓ | ✓ | ✓（流程名/状态/发起人/ID/实例 ID + 节点信息 + 审批信息 + 驳回信息 + 加签信息）| ✗ |
| 定时触发 | ✓ | ✗ | ✗ | ✓（触发方式 / 开始 / 结束 / 周期 / 触发时间）|
| 外部触发 | ✓ | ✗ | ✗ | ✗ |

**子触发类型继承父类**（如「字段值改变触发」自动有「表单触发」的上下文）。

### 4.4 同步与异步（性能开关）

- **同步执行**：触发和执行在同一线程，前端阻塞直到整段完成
- **异步执行**：触发线程释放，后续节点由其他线程处理
- **终端用户无感知差别**

| 触发类型 | 默认 | 是否可切 |
|---|---|---|
| 定时触发 | 异步 | 可 |
| 按钮触发 | 同步 | 否 |
| 外部触发 | 同步 | 可 |
| 表单操作前 | 同步 | 否 |
| 表单操作后 | 异步 | 可 |
| 表单成功后 | 同步 | 否 |
| 字段值改变 | 同步 | 否 |
| 子表操作 | 同步 | 否 |
| 流程进节点前 | 同步 | 可 |
| 流程节点结束后 | 异步 | 可 |
| 流程操作前 | 同步 | 否 |
| 流程操作后 | 异步 | 可 |
| 流程成功后 | 同步 | 否 |

**节点内同步/异步**额外 2 处：
- 提交数据节点（数据量大同步可能 feign 超时，建议异步）
- 循环节点循环方式（同步=每次循环可用上次结果；异步=并行）

### 4.5 目标业务对象（数据操作的"表"）

**核心理解**：增删改查节点操作的不是「表单」，而是「业务对象」（详见数据模型概念）。

**可选类型**：
1. 普通表单/模型表单生成的**自定义业务对象**
2. API 数据模型创建的模型表单生成的**虚拟业务对象**
3. 引用表单生成的业务对象（命名规则：`原应用表单名(当前应用引用表单名)`）

**主子表关系**：
- 选主表业务对象 → 包含其所有子表业务对象（一个整体）
- 选子表业务对象 → 子表数据视为独立数据，可逐条处理

**热更新**：表单改名后业务事件下拉框自动同步。

## 5. 业务事件运维

### 5.1 三大查看入口

| 入口 | UI 路径 | 显示范围 |
|---|---|---|
| 1. 租户业务事件中心 | 后台管理 → 资源配置 → 业务事件 | 整租户所有应用的业务事件 |
| 2. 应用业务事件中心 | 应用详情 → 业务事件 | 当前应用所有业务事件 + 标准工作流（按 外部触发 / 定时触发 / 表单触发 分类）|
| 3. 表单业务事件中心 | 应用详情 → 菜单功能 → 页面设置 → 业务事件 | 当前表单相关的所有业务事件 + 系统操作（埋点视图 + 执行顺序）|

### 5.2 执行历史（关键运维入口）

每个业务事件卡片都有「日志」icon → 弹出执行记录抽屉。

**列表字段**：触发时间 / 执行时长 / 触发方式 / 触发人 / 状态 / 详细记录入口

**详细记录**：按节点顺序展示每节点的输入/输出数据 + 状态

**执行状态**：
- 成功
- 终止（满足终止条件 OR 后端代码报错）
- **无日志特例**：前端 JS 解析失败、外部 API 无返回 → 既不成功也不报错，需要看浏览器 + 容器日志

**节点输入/输出**：树形展示，data 层后是数据条数；每条数据 = 对象字段信息（按业务对象名）+ 系统字段信息（modelField 含 创建人/更新人/创建时间/状态/更新时间/下个审批人/拥有者）。

### 5.3 异常排查指南（官方分布）

> 35% 配置问题 / 15% 外部干扰 / 10% 数据问题 / 5% 设计缺陷 / 剩余=bug

**触发异常**：
- 不触发：F12 看 Console+Network，检查触发节点的数据过滤条件，前端埋点看 Trigger/NormalNode 接口是否调用
- 多次触发：3.2.18.2 及以下 + 自开发分页样式 + 操作成功后 → 升级或改触发方式

**执行异常**：
- 报「网络不给力」=接口报错，按 eventid+nodeid 定位
- 报「业务事件执行异常，请联系管理员」= 节点执行异常，看后台执行记录
- 报「业务事件配置有误」= 历史关联对象被删（节点配置过期）
- 报「业务事件终止」= 查询/校验/调用/弹窗配「事件终止」生效

**实现效果异常**：
- 操作前触发查不到本次数据（数据还没落库，是预期行为）
- 更新新增结果意外（数据来源是查询节点 → 穿透数据权限，与前端看到的不一致）
- 定时触发内部节点不执行（入参为空 → 当前版本判 0 次直接跳过）

**常见报错代码**：
- `NullPointerException` 空指针 = bug，提工单
- `ClassCastException` 类型转换 = 跨组件赋值 bug
- `Database error` 数据库报错 = SQL 不支持或硬性限制

### 5.4 接口层面（关键调用链）

- **前端埋点链路**：浏览器 → `trigger` 接口（触发）→ 每节点 `NormalNode` 接口 → `Complete` 接口 → 后台显示执行记录
- **后端埋点**：浏览器无任何接口，后端监听直接执行
- **外部触发**：POST `<系统生成的触发 URL>`，可选 `xdaptoken` header；返回值由输出节点定义结构
- **外部节点 → 系统字段**：当前用户 Token / 用户 ID / 租户 ID / DocumentId 可直接注入参数

**文档未提供**：业务事件 CRUD 的 backend API 路径（如 `/api/business-events`）— 文档只描述 UI 交互层，没暴露具体 endpoint，需要去实际抓包或读源码确认。

## 6. 给 ai-builder 的启发

> 站在「ai-builder agent 给应用加业务事件配置」的视角

### 6.1 核心架构判断

**得帆的业务事件 = 一套 7×17 矩阵的低代码 BPM 引擎**（7 触发类型 × ~17 执行节点 + 5 通用机制）。要让 agent 配出可用业务事件，**必须**输出 4 类信息：

1. **触发类型 + 完整配置**（含数据过滤条件、是否同步、是否前端埋点）
2. **执行节点 DAG**（节点类型 + 节点参数 + 数据来源指向 + 关联规则/赋值规则）
3. **目标业务对象引用**（不是表单名，是业务对象名 — agent 必须先识别这层映射）
4. **标准上下文变量引用**（如何在赋值/校验中插入"当前用户 ID""触发时间"等）

### 6.2 优先 MVP 切入点（按价值 / 难度）

**P0 — 高价值低复杂度（推荐先做）**：
- **「字段值改变触发 + 查询节点 + 字段赋值」三段式**：覆盖 50% 真实场景（选商机→自动填客户信息），节点少 + 关联规则简单 + 全前端
- **「按钮触发 + 弹窗事件（二次确认）+ 删除/更新数据」**：用户友好的"按钮自动化"，业务方易理解
- **「表单提交后 + 新增数据 + 消息节点」**：表单流转 + 通知一体化

**P1 — 高价值中复杂度**：
- **「定时触发 + 查询 + 循环 + 更新」**：定时清理 / 批处理
- **「外部触发 + 新增数据 + 输出节点」**：开放 API 给外部系统调用
- **审批流程触发**链路（依赖流程设计的理解）

**P2 — 高复杂度，建议后置**：
- **整合节点 + 运算节点 + 自定义节点**：跨表聚合 + 公式计算 + 代码生成，agent 需要理解公式 DSL
- **标准工作流**：引入抽象层，agent 要会判断"什么时候该抽工作流"
- **复杂关联规则**：人员/部门 vs 多选 vs 文本 的字段类型转换矩阵很容易出错

### 6.3 立即可用的 MCP 工具雏形（建议补到 ai-builder mcp-server）

| 工具名 | 入参 | 用途 |
|---|---|---|
| `list_business_objects` | `app_id` | 返回应用下所有业务对象（普通/虚拟/引用）+ 字段结构 — agent 选择目标业务对象的前置 |
| `list_business_events` | `app_id`, `form_id?`, `trigger_type?` | 列出业务事件（参考三大入口） |
| `get_business_event_detail` | `event_id` | 拉触发节点 + 全部执行节点 DAG + 关联规则 |
| `create_business_event` | `app_id`, `trigger_type`, `name`, `nodes[]` | 创建业务事件（一气呵成，参考 ai-builder 现有的 generate_app_from_doc 思路）|
| `validate_business_event_config` | `nodes[]` | 校验 — 前端节点是否被后端触发? 循环内有页面动作? 标准工作流嵌套引用? — 这是 agent 高频出错点 |
| `get_business_event_execution_history` | `event_id`, `limit?` | 拉日志，agent 自查 / 给用户排错 |
| `get_standard_context_for_trigger` | `trigger_type` | 返回该触发类型可用的标准上下文变量列表 — 让 agent 知道能引用什么全局变量 |

### 6.4 Agent prompt / SPEC 必须强调的"铁律"

1. **触发类型创建后不可改** → SPEC 必须先和用户确认触发场景
2. **前端节点不能进后端触发** → 校验失败要早，否则白配
3. **循环节点不能嵌套循环 + 不能含页面动作** → schema 校验
4. **分支节点多条数据按第一条判断流向** → 要逐条判断必须 循环+分支
5. **数据关联规则的字段类型转换矩阵复杂** → agent 优先用「按 ID 匹配」而不是「按名称匹配」避坑
6. **删除数据是物理删除** → 必须二次确认（agent 自动加一个二次确认弹窗节点是好习惯）
7. **目标业务对象 ≠ 表单**：子表有独立业务对象，agent 要在生成时明确选择
8. **同步 vs 异步**：数据量大时主动建议异步（提交节点、循环节点）
9. **外部触发必须配输出节点**否则无返回值
10. **标准工作流不能嵌套引用、不能含页面动作** — 抽工作流时校验

### 6.5 长期价值

得帆"业务事件"本质上是一个**可视化 BPM/规则引擎**，对应业界的：
- n8n / make.com / Zapier（工作流自动化）
- Camunda / Activiti（BPMN 引擎）

ai-builder 若能让 agent **从自然语言一键生成业务事件 DAG**，价值等同于"自然语言写 Zapier 流程"，是 aPaaS Builder agent 的下一个核心差异化能力。建议作为 P0-P1 阶段的重要里程碑。
