# Dolphin Code 30 分钟单人录屏脚本 V2

本文档用于发布会场景 Demo 录屏。脚本按“市场可剪辑素材”设计：一个人讲，录屏时多停顿，关键结果页多停留，方便后期剪成发布会主片、产品短片、销售场景片和技术可信片。

## 整体结构

| 时间 | 环节 | 画面 |
|---:|---|---|
| 00:00 - 02:00 | 开场定位 | Dolphin Code 首页 |
| 02:00 - 05:00 | 界面导览 | Builder / Code、应用、会话 |
| 05:00 - 16:00 | Demo 1：AI Native 应用设计 | 销售线索评分与跟进助手 |
| 16:00 - 23:00 | Demo 2：低代码老客户应用二开 | 项目风险预警助手 |
| 23:00 - 28:30 | Demo 3：Agentic 测试与部署 | 测试与部署计划 |
| 28:30 - 30:00 | 总结 | 三个 Demo 成果页 |

## 00:00 - 02:00 开场定位

画面：Dolphin Code 主界面，左侧 Builder / Code 可见。

讲述：

> 大家好，我今天演示 Dolphin Code。
> 它不是一个单独的代码助手，而是面向企业应用生产的 AI Coding 工作台。
>
> 在 Dolphin 体系里，Builder 更偏低代码应用设计和配置，Code 更偏 AI Coding、多智能体协作、复杂二开、测试和部署。
>
> 过去无代码和低代码解决的是“怎么更快做出应用”。
> 但进入 AI Native 阶段之后，企业应用还需要解决一个新问题：
> 这个应用能不能被 Agent 理解？能不能被 Agent 调用？能不能和人一起完成业务流程？
>
> 今天我会用三个场景演示：
> 第一，从一个业务想法生成 AI Native 应用设计。
> 第二，让已有低代码应用升级为 Agentic 应用。
> 第三，测试和部署时，不只测试人怎么用，也测试 Agent 怎么用。

停顿 2 秒，给后期剪辑。

金句：

> Dolphin Code 不是从代码开始，而是从企业应用开始。

## 02:00 - 05:00 产品界面导览

画面动作：

1. 鼠标停在 Builder / Code 切换。
2. 点击 Builder，再点击 Code。
3. 展示左侧“我的应用”。
4. 展示应用下的历史会话。
5. 展示右侧对话工作区。

讲述：

> 先看一下界面。
> 左侧这里是 Builder 和 Code 的切换。Builder 面向低代码应用配置，Code 面向 AI Coding 和多智能体协作。
>
> Code 不是按本地文件夹组织工作的，而是按企业应用组织工作的。
> 这里每个应用下面都有自己的会话历史。
> 也就是说，我们不是先打开一个项目再问 AI 怎么改代码，而是围绕一个应用持续做设计、开发、测试和部署。

画面：指向当前应用组，例如 CRM。

> 比如这个 CRM 应用，下面可以有多个 Code 会话。
> 一个会话可以做需求设计，一个会话可以做二开，一个会话可以做测试和部署。
> 应用、会话、上下文都被组织在一起，后续协作会更清晰。

画面：右侧输入区。

> 右侧是对话式工作区。
> 在这里，我可以直接输入业务目标，也可以要求它读取已有应用、生成变更方案、补齐测试用例，或者生成部署计划。

金句：

> Dolphin Code 不是孤立写代码，而是围绕企业应用持续交付。

## 05:00 - 16:00 Demo 1：AI Native 应用设计

Demo 主题：

> 从一个业务想法，到一个可交互的专业应用原型。

### 05:00 - 06:00 任务输入

画面动作：新建或打开 Demo 1 会话，输入：

```text
帮我设计一个“销售线索评分与跟进助手”应用。这个应用要支持销售查看线索、自动计算评分、生成跟进建议，同时页面里要有业务助手，可以随时查询客户、线索、商机和跟进记录。
```

讲述：

> 第一个 Demo，我从一个很自然的业务想法开始。
> 我不是先写 PRD，也不是先建表，而是直接描述业务目标：
> 我要做一个销售线索评分与跟进助手。

发送任务。

> Dolphin Code 首先不会急着写代码，而是先理解这个业务想法背后的应用结构。

剪辑建议：等待过程保留 3 秒即可，后期可倍速或跳切。

### 06:00 - 07:30 需求拆解

画面：展示需求拆解结果。

讲述：

> 第一阶段是需求设计智能体。
> 它会把一句业务想法拆成几个核心目标：
> 销售如何查看线索，系统如何计算评分，如何生成跟进建议，以及业务助手在页面里能做什么。
>
> 这里有一个关键点：它不是只理解页面，而是理解业务对象。
> 比如客户、线索、商机、跟进记录，这些对象之间有什么关系，后续页面和 Agent 能力都要围绕这些对象展开。

画面停留：

- 业务目标
- 核心对象
- 业务流程
- Agent 能力边界

金句：

> AI Native 应用设计的第一步，不是页面，而是业务对象和业务目标。

### 07:30 - 08:50 用户和使用场景

画面：展示使用场景或角色分析。

讲述：

> 接下来，它会识别这个应用的使用场景。
> 例如销售每天要看哪些线索最值得跟进；团队管理者要看整体转化情况；运营人员要维护评分规则；管理员要控制权限和数据范围。
>
> 这些场景会影响后面的页面结构、字段设计、权限设计和 Agent 能力设计。

展示建议：

| 使用场景 | 应用能力 |
|---|---|
| 查看高分线索 | 线索列表、评分排序 |
| 分析线索质量 | 评分原因、评分构成 |
| 制定跟进动作 | 跟进建议、邮件生成 |
| 管理评分规则 | 规则配置、权重维护 |
| 查询业务数据 | 业务助手查询客户、线索、商机 |

### 08:50 - 10:10 功能模块生成

画面：展示功能模块。

讲述：

> 在理解场景之后，它会生成应用模块。
> 这个应用至少包括线索列表、线索详情、评分规则、跟进建议、业务助手和报表看板。
>
> 这一步非常关键，因为它把一句“我要一个助手”，变成了一个真正可设计、可开发、可测试的企业应用结构。

画面停留模块：

- 线索列表
- 线索详情
- 评分规则
- 跟进建议
- 业务助手
- 报表看板

金句：

> Dolphin Code 把业务想法拆成可以交付的应用模块。

### 10:10 - 12:20 UI / UE / UX 设计

画面：展示页面结构、原型说明或应用原型。

讲述：

> 现在进入 UI 和交互设计阶段。
> 它生成的不是一个孤立页面，而是一组围绕销售工作流设计的应用界面。
>
> 比如线索列表要突出评分、等级、来源、负责人和最近跟进时间。
> 线索详情页要展示客户画像、评分构成和历史互动。
> 报表看板要展示线索来源、转化漏斗和高分线索排行。

画面指向业务助手入口。

> 这里重点看业务助手。
> 它不是简单放一个聊天框，而是和当前页面上下文绑定。
> 当用户在线索详情页时，助手知道当前线索是谁，可以解释评分原因，也可以推荐下一步动作。

金句：

> AI Native 应用不是把 Agent 贴到页面上，而是在应用设计阶段就定义 Agent 如何参与业务。

### 12:20 - 14:00 功能设计和数据模型

画面：展示字段、规则、权限、流程设计。

讲述：

> 接下来功能设计智能体会补齐字段、规则、权限和流程。
> 例如线索对象需要基础信息、来源、预算、行业、互动次数、评分、评分原因和跟进状态。
> 评分规则可以由运营维护，系统根据线索来源、客户规模、互动频率等信息自动计算分数。

展示数据模型：

| 对象 | 关键字段 |
|---|---|
| 客户 | 名称、行业、规模、联系人 |
| 线索 | 来源、预算、评分、等级、状态 |
| 商机 | 阶段、金额、预计成交时间 |
| 跟进记录 | 跟进方式、内容、下一步动作 |
| 评分规则 | 条件、权重、有效期 |

讲述：

> 所以最后产物不是一句回答，而是一套可落地的应用设计说明。

### 14:00 - 15:20 Agentic 能力说明

画面：展示 Agent 可调用功能说明。

讲述：

> 最后，它会明确 Agentic 能力。
> 业务助手可以查询客户、线索、商机和跟进记录；可以解释评分；可以推荐下一步动作；还可以生成跟进邮件。
>
> 这些能力不是泛泛的聊天能力，而是和业务对象、权限、流程绑定在一起。

展示表：

| Agent 能力 | 示例 |
|---|---|
| 查询单据 | 查某客户所有线索 |
| 解释评分 | 为什么这条线索是 A 级 |
| 推荐动作 | 建议今天电话跟进 |
| 生成邮件 | 生成客户跟进邮件 |
| 风险提醒 | 找出 7 天未跟进高分线索 |

### 15:20 - 16:00 Demo 1 总结

画面：最终结果页。

讲述：

> 到这里，第一个 Demo 就完成了。
> 我们从一句业务想法，得到了专业应用原型、页面布局、交互说明、功能设计、数据模型，以及 Agent 助手入口和可调用能力说明。
>
> 这就是 Dolphin Code 面向 AI Native 应用设计的价值。

金句：

> Dolphin Code 不是生成一个页面，而是设计一个能与人和 Agent 协同工作的应用。

## 16:00 - 23:00 Demo 2：低代码老客户应用二开

Demo 主题：

> 让已有低代码应用升级为 Agentic 应用。

### 16:00 - 17:00 场景引入

画面：切换到项目管理应用或对应会话。

讲述：

> 第二个场景是老客户非常常见的需求。
> 一个项目管理应用已经上线运行了，客户不想推倒重做，而是希望在原有系统上增加智能能力。
>
> 所以这个 Demo 不是从 0 到 1 新建应用，而是在已有低代码应用上做二开。

输入：

```text
已经运行的项目管理应用，现在客户要求增加一个“项目风险预警助手”：根据延期天数、预算偏差、未关闭问题数自动生成风险等级，并在项目列表和详情页展示，同时业务助手可以查询项目状态、解释风险原因、生成整改建议，并触发通知。
```

### 17:00 - 18:30 读取已有应用

画面：展示读取页面、表单、数据模型、流程配置。

讲述：

> Dolphin Code 会先读取已有低代码应用。
> 它会理解当前有哪些页面、表单、字段、数据模型和流程配置。
>
> 比如项目对象里已经有项目名称、负责人、截止日期、预算、实际成本、状态；问题对象里有未关闭问题数；流程里可能已经有项目审批和通知。

屏幕重点：

- 项目列表页
- 项目详情页
- 项目字段
- 问题 / 任务 / 预算模型
- 现有流程

金句：

> 老应用二开最重要的不是生成新东西，而是先理解旧系统。

### 18:30 - 20:10 生成增量变更方案

画面：展示新增字段和变更说明。

讲述：

> 在理解已有应用之后，它生成的是增量变更方案。
> 不是另起一套项目管理系统，而是在原有模型上新增字段和规则。
>
> 比如新增风险等级、风险原因、预警时间。
> 项目列表增加风险标签和筛选条件。
> 项目详情页增加风险解释卡片。
> 流程里增加高风险通知动作。

展示表：

| 变更项 | 内容 |
|---|---|
| 新增字段 | 风险等级、风险原因、预警时间 |
| 计算规则 | 延期天数、预算偏差、未关闭问题数 |
| 列表页 | 增加风险标签、风险筛选 |
| 详情页 | 增加风险解释卡片 |
| 通知动作 | 高风险通知负责人 |

### 20:10 - 21:40 Agentic 升级

画面：展示业务助手可调用功能。

讲述：

> 这次二开不只是增加字段和页面。
> Dolphin Code 会同时设计 Agent 可调用能力。
>
> 项目风险预警助手可以查询项目状态，解释为什么这个项目被判定为高风险，生成整改建议，并在必要时触发通知。
>
> 这就是 Agentic 应用二开的重点：页面、数据、流程和 Agent 能力一起升级。

展示：

| Agent 能力 | 示例 |
|---|---|
| 查询项目状态 | 这个项目为什么延期 |
| 解释风险原因 | 风险来自预算还是进度 |
| 生成整改建议 | 给项目经理生成行动建议 |
| 触发通知 | 高风险时通知负责人 |
| 权限控制 | 只能查权限范围内项目 |

金句：

> 低代码二开不只是改页面，而是让已有应用获得 Agent 能力。

### 21:40 - 22:40 变更说明和测试建议

画面：展示变更说明、测试建议。

讲述：

> 最后，它会输出变更说明和测试建议。
> 研发可以知道改了哪些字段，测试可以知道要验证哪些规则，业务也能看懂这次升级带来的价值。

展示：

- 字段变更
- 页面变更
- 流程变更
- Agent 能力变更
- 测试建议

### 22:40 - 23:00 Demo 2 总结

画面：停在结果页。

讲述：

> 对老客户来说，Dolphin Code 的价值不是替换已有低代码系统，而是让已有应用持续进化。

金句：

> Dolphin Code 让已有低代码应用，从“能用”升级为“能被 Agent 使用”。

## 23:00 - 28:30 Demo 3：Agentic 应用测试与部署

Demo 主题：

> 不只测试页面，也测试 Agent 如何使用应用。

### 23:00 - 24:00 测试任务输入

画面：切到测试部署会话。

输入：

```text
请为销售线索评分与跟进助手生成测试方案。除了传统功能测试，还要覆盖业务助手查询单据、解释评分、生成跟进建议、权限隔离、人工确认和多环境部署。
```

讲述：

> 第三个场景是测试和部署。
> 传统应用主要测试页面和流程，但 AI Native 应用还要测试 Agent 怎么使用应用。
>
> 因为 Agent 不只是看页面，它会查询数据、解释结果、生成建议，甚至触发动作。

### 24:00 - 26:10 功能测试和 Agentic 测试

画面：展示测试用例。

讲述：

> Dolphin Code 会生成两类测试。
> 第一类是传统功能测试，比如字段校验、评分规则、页面展示、权限控制。
> 第二类是 Agentic 测试，比如业务助手能不能查到正确单据，能不能解释评分原因，能不能在发送邮件或触发通知前进入人工确认。

展示表：

| 测试类型 | 示例 |
|---|---|
| 功能测试 | 评分规则计算正确 |
| 页面测试 | 列表和详情展示评分等级 |
| Agent 查询测试 | 查询客户线索结果准确 |
| Agent 解释测试 | 评分原因可追溯 |
| 权限测试 | 销售不能访问其他团队数据 |
| 人工确认测试 | 发送邮件前需要确认 |
| 审计测试 | Agent 操作可记录、可追踪 |

金句：

> AI Native 应用不仅要测人怎么用，也要测 Agent 怎么用。

### 26:10 - 27:50 多环境部署计划

画面：展示开发、测试、生产环境部署计划。

讲述：

> 除了测试，它还会生成多环境部署计划。
> 开发环境用于联调，测试环境用于测试数据和权限验证，生产环境需要灰度、回滚和监控策略。
>
> 这说明 Dolphin Code 不只是 Demo 生成器，而是面向真实企业交付的工程化工作台。

展示表：

| 环境 | 重点 |
|---|---|
| 开发 | 联调、Mock 数据 |
| 测试 | 测试账号、权限、规则验证 |
| 生产 | 灰度发布、回滚、监控、审计 |

### 27:50 - 28:30 Demo 3 总结

画面：测试结果页。

讲述：

> 当 Agent 开始参与业务，测试和部署也要升级。
> 我们不仅要验证页面能不能用，还要验证 Agent 能不能安全、准确、可控地使用应用。

金句：

> Agentic 应用的质量，不只来自功能测试，也来自 Agent 行为测试。

## 28:30 - 30:00 总结收束

画面：回到 Code 左侧应用和三个会话，或切换展示三个 Demo 结果。

讲述：

> 总结一下，今天三个 Demo 展示了 Dolphin Code 的完整价值。
>
> 第一，从业务想法出发，生成 AI Native 应用设计。
> 第二，在已有低代码应用上做智能化二开。
> 第三，把 Agent 的查询、解释、权限、确认和部署纳入工程化测试。
>
> Dolphin Code 的目标不是简单帮研发写代码，而是把企业应用生产从无代码、低代码、高代码，进一步升级到 AI Coding 和多智能体协作。
>
> 它让业务人员可以参与应用设计，让 IT 和研发更快完成应用交付，也让低代码老客户的已有应用持续升级为 Agentic 应用。

最终金句：

> Dolphin Code，让企业应用不仅被人使用，也能被 Agent 理解、调用和持续进化。
