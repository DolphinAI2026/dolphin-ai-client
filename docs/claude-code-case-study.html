Part 01

项目背景

得帆云是一款面向企业的低代码开发平台（aPaaS），提供数据模型、表单设计、流程编排、权限管理等核心能力。然而，传统低代码平台的学习曲线依然陡峭——用户需要手动配置数十个参数才能搭建一个完整的业务应用。

aPaaS Builder AI 正是为解决这一问题而生：通过对话式 AI 助手，让用户用自然语言描述需求，系统自动生成完整的应用配置并一键部署至平台。

💬
智能搭建
多轮对话收集需求 → AI 生成配置 → 一键创建数据模型、表单与权限
🎨
Vibe Coding
对话式自开发：AI Agent 编写 Vue 组件，实时沙箱预览，一键上传平台
📦
应用管理
查询、更新、增量修改已有应用配置，无需重建
⚙️
多环境管理
支持多 aPaaS 实例，灵活切换 LLM 供应商（Claude / MiniMax / Qwen）

Part 02

Claude Code 的应用方式

项目团队面临三大挑战：AI 功能复杂（需要同时实现两套 Agent 系统）、aPaaS API 学习成本高（文档分散）、快速迭代压力。Claude Code 的深度代码理解 + 多文件协作编辑 + 长上下文对话能力恰好覆盖了这些痛点。

1

Skills 文档驱动的 API 集成

项目在 skills/ 目录维护了 28 个 Markdown 技能文件，每个文件精确描述一个 aPaaS API 的调用方式、参数规范和注意事项。

skills/
├── apaas-create-model-field.md    # 创建数据模型字段
├── apaas-create-dict-value.md     # 创建数据字典值
├── apaas-create-permission.md     # 创建权限组
├── apaas-comp-checkbox.md         # 复选框组件规范
├── apaas-comp-association.md      # 关联字段组件规范
├── apaas-deploy-app.md            # 应用部署流程
└── ...（共 28 个）

将 skill 文件作为上下文喂给 Claude Code，API 集成首次成功率从约 60% 提升至 90%+。

3

系统提示词（Prompt）工程

backend/app/coding/prompts.py 中的 system prompt 经过与 Claude Code 深度对话打磨，关键优化点：

优化点原始问题解决方案
轮数限制Agent 反复读文件，消耗大量 token"最多 8 轮，立即并行写完所有文件"
依赖管理手动修改 package.json 导致版本冲突"第三方依赖必须 npm install，禁止手动编辑"
参考隔离参考已有组件引入结构污染"不读其他组件目录，只看自己的工作区"
错误反馈上传失败信息不透传给用户明确要求原始错误信息直接返回
4

CLAUDE.md 规范治理

项目根目录的 CLAUDE.md 文件作为 Claude Code 的"宪法"，规定 AI 在此项目中的行为边界。每次 Claude Code 犯了新错误，就在 CLAUDE.md 中增加一条约束，形成"Bug → 规则"的经验沉淀机制。

# CLAUDE.md（节选）

## 禁止事项
- 禁止参考已有工作区的组件代码（防止污染）
- 禁止手动编辑 package.json（必须用 npm install）
- 禁止生成伪全局变量（this.$xxx 不可用）
- widget.config.js 中的元数据必须与实际功能一致

## 开发规范
- 第三方依赖安装后必须 import，不能假设全局可用
- 组件必须通过 npm run build 验证后再上传

工程化实践要点

CLAUDE.md 的核心价值：不同于通用 AI 助手，Claude Code 能读取项目 CLAUDE.md 并将其作为持久化上下文规范——每次新对话无需重复交代背景，团队规范自动注入 AI 行为，Bug 经验自动成为约束条件。
多文件协作编辑：Claude Code 的多文件编辑能力使重构变得简单——"将 VibeCodingAgent 的工具执行逻辑提取到独立的 tools.py，保持接口兼容"，Claude Code 能一次性理解依赖关系并完成所有改动。

推广建议

适合引入的场景

适合不适合
✓ 有清晰 API 文档的集成工作 ✗ 需要大量人工判断的产品决策
✓ 多文件的重构和代码迁移 ✗ 高度定制化的底层性能优化
✓ 重复性的模板代码生成 ✗ 需要深度领域专家知识的算法设计
✓ 测试用例编写 ✗ 初次接触的全新技术栈探索
✓ Prompt 工程迭代 ✗ 安全敏感的核心加密逻辑

落地路径建议

1
阶段一：个人试用（第 1–2 周）
选择中等复杂度功能模块，用 Claude Code 辅助实现。观察哪些任务效率提升最明显，哪些场景容易出错。产出：个人使用经验文档。
2
阶段二：团队规范（第 3–4 周）
建立团队共用的 CLAUDE.md，沉淀 API 规范、代码风格、禁止事项。建立 skill 文件库，将内部 API 文档转化为 Claude Code 可直接使用的格式。
3
阶段三：流程融合（第 5–8 周）
将 Claude Code 纳入日常 Code Review 流程。建立"Bug → CLAUDE.md 规则"经验沉淀机制。评估 ROI，形成可量化的效率报告。

CLAUDE.md 编写建议

# 好的 CLAUDE.md 结构

## 项目概述（1段话）
让 AI 快速理解项目是什么

## 技术栈（列表）
明确版本号和选型原因

## 禁止事项（重要！）
来自真实 Bug 的经验教训，越具体越好

## 开发规范
目录结构、命名约定、代码风格

## 常用命令
启动、测试、部署命令

## 注意事项
API 特殊行为、已知坑点
关键原则：禁止事项优先于规范（AI 遵守禁令效果优于正向规范）；每条规则背后都应有真实发生过的问题；持续更新，每次出新 Bug 就增加新规则。

常见误区

误区 01
"Claude Code 能替代开发者"
实际上它更像"10x 效率的结对伙伴"——需要开发者提供清晰需求、审核输出结果、处理边界情况。
误区 02
"直接用，不需要配置"
没有项目上下文的 Claude Code 效果有限。投入 1-2 天建立 CLAUDE.md 和 skill 文件，是获得长期收益的关键投资。
误区 03
"生成代码不需要 Review"
Claude Code 偶尔会引入安全漏洞或逻辑错误。保持 Code Review 习惯，重点关注安全边界和业务逻辑。
误区 04
"只能用于新功能开发"
重构、测试、文档生成、Bug 定位往往是 Claude Code ROI 最高的场景，不要只在新功能开发时才用。

aPaaS Builder AI 项目是一个"用 AI 构建 AI 产品"的典型案例。Claude Code 在其中不仅是开发工具，更是架构决策的协作者——VibeCodingAgent 的设计借鉴了 Claude Code 自身的 Agent 模式，Prompt 工程的最佳实践来自与 Claude Code 的深度对话，CLAUDE.md 的规则体系则是团队与 AI 共同进化的经验结晶。
