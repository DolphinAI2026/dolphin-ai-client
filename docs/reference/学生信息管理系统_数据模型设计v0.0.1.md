# 学生信息管理系统 - 数据模型设计

## 1. 数据模型（Models）

| 模型名称 | 模型编码 | 说明 |
|---------|---------|------|
| 学生信息 | `student_info` | 核心学生档案 |
| 班级 | `class_info` | 班级管理 |
| 课程 | `course` | 课程信息 |
| 成绩记录 | `score_record` | 学生成绩 |
| 教师 | `teacher` | 教师信息 |
| 院系 | `department` | 院系/学院 |

## 4. 角色设计（Roles）

| 角色名称 | 角色编码 | 权限范围 |
|---------|---------|---------|
| 系统管理员 | `sys_admin` | 全部数据读写、系统配置 |
| 教务管理员 | `edu_admin` | 学生/班级/课程/成绩 全部读写 |
| 院系管理员 | `dept_admin` | 本院系学生/班级/教师 读写 |
| 教师 | `teacher_role` | 自己的课程、所教学生成绩读写 |
| 班主任 | `head_teacher` | 本班学生信息读写 |
| 学生 | `student_role` | 仅查看自己的信息和成绩 |

### 权限矩阵

| 模型 | 系统管理员 | 教务管理员 | 院系管理员 | 教师 | 班主任 | 学生 |
|-----|-----------|-----------|-----------|------|-------|-----|
| 学生信息 | CRUD | CRUD | CRUD(本院) | R | RU(本班) | R(自己) |
| 班级 | CRUD | CRUD | RU(本院) | R | R | R |
| 课程 | CRUD | CRUD | RU | RU(自己) | R | R |
| 成绩记录 | CRUD | CRUD | R(本院) | CRU(自己) | R(本班) | R(自己) |
| 教师 | CRUD | CRUD | RU(本院) | R | R | R |
| 院系 | CRUD | CRUD | R | R | R | R |

> CRUD = Create, Read, Update, Delete

## 5. 模型关系图

```
┌─────────────┐     ┌─────────────┐
│  department │◄────│   teacher   │
│    院系     │     │    教师     │
└──────┬──────┘     └──────┬──────┘
       │                   │
       │ 1:N               │ 1:N
       ▼                   ▼
┌─────────────┐     ┌─────────────┐
│  class_info │◄────│   course    │
│    班级     │     │    课程     │
└──────┬──────┘     └──────┬──────┘
       │                   │
       │ 1:N               │
       ▼                   │
┌─────────────┐            │
│student_info │◄───────────┘
│  学生信息   │      N:M (通过score_record)
└──────┬──────┘
       │
       │ 1:N
       ▼
┌─────────────┐
│score_record │
│  成绩记录   │
└─────────────┘
```

## 6. 得帆云平台创建顺序

建议按以下顺序在得帆云平台创建资源：

1. **数据字典** - 先创建所有字典（gender_dict, student_status_dict 等）
2. **院系模型** - 无依赖，优先创建
3. **教师模型** - 依赖院系
4. **班级模型** - 依赖院系、教师
5. **学生信息模型** - 依赖班级
6. **课程模型** - 依赖教师
7. **成绩记录模型** - 依赖学生、课程
8. **角色配置** - 最后配置各角色权限
