## 一、平台定位与整体架构

**apaas-builder-ai** 是得帆云低代码平台（aPaaS）的 AI 搭建助手。用一句话概括：

> 用户描述或上传需求文档 → AI 全自动生成 aPaaS 应用（数据模型、表单、菜单、角色、流程）→ 直接发布上线，免低代码手工搭建。

平台同时向外部 agent 平台（Dolphin）暴露 MCP 工具集，定位为"MCP 工具供应商"。内置的对话界面是过渡形态，长期以 Dolphin 驱动为主。

### 组件拓扑

```
                           浏览器 (HTTPS)
                                │
                  ┌─────────────┴──────────────┐
             nginx（宿主 / k8s sidecar）
                  │               │              │
            /ai-builder/      /api/           /ide/
              前端 dist      uvicorn         code-server
           (Vue3 SPA,        :8003           :8080
            打进镜像)          │
                    ┌─────────┼─────────────┐
                    │         │             │
              aPaaS 平台    LLM 网关      MySQL
              (得帆云,       (MiniMax /    (外置,
               低代码 PaaS)   Dolphin 等)   业务库)
                    │
              [内嵌 MCP Server]
              /api/mcp/mcp  ←── Dolphin / 外部 agent
              111 个 @mcp.tool()

  旁路：uvicorn ──docker.sock / k8s API──▶ Vibe 沙箱 Pod
```

**部署形态**：单容器多进程（supervisord 托管 uvicorn + code-server）+ 宿主/sidecar nginx + 外置 MySQL。容器不自带数据库。

**技术方向**：代码库 ~20 万行（Python 11.5 万 + Vue/TS 8.8 万），已在得帆公司 KubeSphere k8s 集群生产运行。

## 二、功能全景

### 2.1 后端 API（177 端点 / 40+ 路由域）

| 能力域 | 规模 | 状态 |
|--------|------|------|
| 认证与多租户 | 9 端点，JWT HS256，4 ID claims | 生产就绪 |
| 对话管理（ChatPage 路径） | 7 端点，SSE 流，SpecAgent | 生产就绪 |
| AI Chat（AIChatPage 路径） | 11 端点，agent loop，6 内置工具 | 生产就绪 |
| 应用管理（含生成/发布/回滚） | ~40 端点，分步生成 + 增量更新 | 生产就绪 |
| Vibe Coding 工作区 | ~50 端点，文件/构建/浏览器控制/IDE 集成 | 基本就绪（沙箱依赖 docker.sock / k8s） |
| Coding V2 Orchestrator | 8 端点，状态机驱动（UNDERSTAND→VERIFY→DONE） | 生产就绪 |
| 项目协作 / Git 集成 | 10 端点 | 可选功能 |
| 平台代理（透传 aPaaS） | /xdap-admin / /xdap-app / /backend / /platform 等 | 生产就绪 |
| LLM 配置管理 | 8 端点，多 provider 支持 | 生产就绪 |
| MCP Server（对外工具） | /api/mcp/mcp（现代）+ /api/mcp-legacy/sse（兼容）| 生产就绪 |

### 2.2 内嵌 MCP：111 个工具，三类 agent 白名单

| agent 白名单 | 可用工具数 | 典型用途 |
|-------------|-----------|---------|
| config（ConfigAssistant，右侧配置助手） | 78 | 对话修改 aPaaS 平台任意配置 |
| builder（Dolphin Builder Agent） | 47 | 从设计文档建完整 aPaaS 应用 |
| coding（Dolphin Coding Agent） | 38 | 自开发组件 + 工作区操作 |

工具按域分：读取平台（17）/ 业务事件（11）/ 浏览器控制（11）/ 文档→应用管线（9）/ 平台更新（9）/ 生命周期（6）/ 删除（6）/ 创建（5）/ 其他（37）。

### 2.3 前端：25+ 页面，两条独立链路

```
链路 A：设计生成
  Landing(/) → AIChatPage(/ai-chat) → agent SSE → 设计文档 artifact
                    → 生成应用 → CTA 跳 ChatPage

链路 B：配置调整
  Apps(/apps) → ChatPage(/chat?app_id=N)
                    SectionNav 5 Tab:
                    设计(表单/列表/SPEC) · 数据(模型/字典)
                    逻辑(流程) · 权限(角色矩阵/表单权限) · 运行(日志/预览)
                    + 右侧 ConfigAssistantPanel（常驻 AI 对话）
```

⚠️ `/ai-chat`（AIChatPage）与 `/chat`（ChatPage）是完全不同的两个页面，功能和路由守卫均不同，千万不要混淆。

admin-spa 独立打包，提供 MCP 服务管理、测试台、工作区监控、调用日志等运营视图（共 10 个路由）。

### 2.4 核心生成管线（文档 → aPaaS 应用）

```
用户上传设计文档 (md / docx / pdf)
    ↓ doc_parser.py 解析标准化
    ↓ Application.config 存 MySQL
    ↓ generator_v2.py::run_complete_generation()
       Phase 0  解析配置
       Phase 1  创建角色 + 数据字典
       Phase 2  创建数据模型（批量建，失败单条降级）
       Phase 3  创建表单 + 绑定字典
       Phase 4  配置权限
    ↓ step_executor.py（分步幂等，支持单步重试）
    ↓ apaas_client.py（httpx → aPaaS REST API，共 2429 行）
    ↓ aPaaS 平台应用上线
```

增量更新走 `incremental_executor.py`（config_diff → 逐项调 aPaaS API → 回写本地状态），含指数退避（MAX_RETRIES=2）防重试风暴。
