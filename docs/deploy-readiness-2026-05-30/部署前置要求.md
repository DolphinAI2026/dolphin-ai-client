# 客户部署前置要求 — apaas-builder（Docker Compose 单机）

> 日期：2026-05-30 ｜ 目标形态：**单机 Docker Compose**（团队已验证的 `deploy/docker/` 编排 + `deploy/customer/` 加固脚本）

> 配套阅读：[部署盘点](05-deployment-inventory.md)（权威环境变量表/拓扑） · [安全报告](04-security-findings.md)（上线前必办加固）

## 0. 一句话

平台 = **一个容器**（supervisord 托管 uvicorn 后端 + 可选 code-server）+ **前置 nginx**（serve 前端 dist + 反代 /api）+ **外置 MySQL**。容器**不自带数据库**。最大的三个非脚本能解的前置是：① 镜像要预构建交付（客户拉不到内网私库）；② 必须连客户自己的 aPaaS + LLM；③ 第一个管理员要靠脚本 seed（已解决）。

---

## 1. 基础设施前置

| 项 | 要求 | 说明 |
|---|---|---|
| 主机 | Linux，建议 ≥ 4C / 8G / 50G 磁盘 | 单节点即可 |
| Docker | Docker Engine + `docker compose` v2 | `deploy.sh` 会校验 |
| **外置 MySQL** | 5.7+ / 8.0，**预建空库 + 授权账号** | 如库 `apaas_builder`（`utf8mb4`）；容器首启自动建表（无需手工建表）。**口令必须强随机**（别用文档里的 `apaas2024`） |
| 域名 + TLS | 一个域名 + 证书，前置 nginx 终止 TLS | 浏览器麦克风 / 部分功能需 HTTPS |
| 前置 nginx | serve 前端 dist + 反代 `/api`→后端 + （可选）`/ide`→code-server | 参考 [`deploy/docker/nginx.conf.example`](../../deploy/docker/nginx.conf.example)；**务必补安全响应头**（见 §7） |

## 2. 镜像交付（🔴 头号前置）

镜像默认只在内网私库 `hub.dfy.definesys.cn`，**客户拉不到**。二选一：

- **离线导出（推荐）**：交付方在能联网机器上构建并导出
  ```bash
  cd <repo> && docker build -t apaas-builder:latest -f deploy/docker/Dockerfile .
  docker save apaas-builder:latest -o apaas-builder.tar
  # 客户侧部署时： IMAGE_TAR=/path/apaas-builder.tar ./deploy/customer/deploy.sh
  ```
- **现场构建**：客户主机能访问公网（构建期要拉 Node/code-server/docker-CLI/apt），直接 `deploy.sh` 会用本地 build。多数私有化客户不具备，**优先用离线导出**。
- 若启用 Vibe Coding（默认关），还需预构建 `vibe-sandbox:latest`（`docker/vibe-sandbox/`）。

## 3. 必填配置（写进 `backend.env`，`deploy.sh` 首次运行会生成模板让你填）

| 变量 | 必填 | 来源 |
|---|---|---|
| `DATABASE_URL` | ✅ | 客户 MySQL：`mysql+aiomysql://用户:口令@主机:3306/apaas_builder?charset=utf8mb4` |
| `APAAS_BASE_URL` + `APAAS_TENANT_ID` | ✅ | **客户自己的 aPaaS 平台**（覆盖得帆 POC 默认） |
| `LLM_API_KEY` + `ANTHROPIC_BASE_URL` + `ANTHROPIC_API_KEY` | ✅ | 客户的 LLM 网关（OpenAI/Anthropic 兼容） |

> 缺 `LLM_API_KEY` / `JWT_SECRET_KEY` 后端**启动直接崩**。

---

## 4. 密钥（`deploy.sh` 自动随机生成，切勿手填弱值/默认值）

`JWT_SECRET_KEY`、`ENCRYPTION_KEY`、`BUILDER_FERNET_KEY`、`MCP_API_KEYS` —— 脚本首次运行用 `openssl` 随机生成并写入 `backend.env`（权限 600，不入库/不入镜像），**再次运行不覆盖**（避免重置 `ENCRYPTION_KEY` 导致已加密数据无法解密）。
⚠️ 三把密钥都有不安全的硬编码默认值（安全报告 C-2 / H-8），**绝不能用默认值上生产**。

---

## 5. 首个管理员（已解决原「无 aPaaS 无管理员」阻塞）

平台默认靠「登录时镜像 aPaaS 用户」自举，seed 不建用户。`deploy.sh` 会在健康检查后自动执行 [`backend/scripts/create_admin.py`](../../backend/scripts/create_admin.py) 创建一个本地平台管理员（`ADMIN_USERNAME`/`ADMIN_PASSWORD`，默认 admin + 随机口令，末尾打印）。
- 客户若接了自己的 aPaaS，也可直接用 aPaaS 管理员账号首登自举，本地 seed 账号作兜底。

## 6. 网络出口（客户主机需出站可达）

| 目标 | 必须 | 说明 |
|---|:--:|---|
| 客户 MySQL | ✅ | 不通起不来 |
| 客户 aPaaS 平台 | ✅ | 登录自举 / 应用上线 / 平台代理全靠它，不通则产品无价值 |
| 客户 LLM 网关 | ✅ | AI 搭建核心 |
| dolphin / GitHub / 私有 npm 源 | ❌ | 按需，不配不影响核心 |

## 7. 🛑 上生产前必办的安全加固（脚本改不了，须人工改代码/编排——详见[安全报告](04-security-findings.md)）

> 本平台**功能成熟但安全默认值不达生产标准**。以下为交付客户前的红线项，按优先级：

1. **平台代理鉴权（C-1，最高优先）**：`platform_proxy` 全部路由加 `Depends(get_auth_context)`、删 `proxy_init`、废弃进程级全局 `_proxy_state` 单例——否则未认证者可越权调 aPaaS、多租户数据串号。
2. **轮换泄漏密钥 + 清 git 历史（C-3/C-4）**：README/文档里明文的 `JWT_SECRET_KEY`/`LLM_API_KEY` 已泄漏且在 git 全历史，必须轮换 + `git filter-repo` 清除 + 删模板里 4 份 RSA 私钥。
3. **容器降权（H-4）**：现 compose 用 host 网络 + 挂 `docker.sock`（逃逸=宿主 root）。脚本已设 `VIBE_CODING_RUNTIME=host`（不用沙箱），**可手动从 `deploy/docker/docker-compose.yml` 删掉 docker.sock 挂载**；并给 Dockerfile 加非 root `USER`。
4. **Web IDE（H-5）**：脚本默认 `CODE_SERVER_BASE_URL=` 留空禁用。若启用，必须给 nginx `/ide/` 加鉴权（code-server 是 `--auth none`）。
5. **nginx 安全头（M-5）**：补 `HSTS`/`X-Frame-Options`/`X-Content-Type-Options`/`CSP`/`Referrer-Policy`。
6. **口令哈希（H-1）**：本地账号口令现用无盐 SHA-256，迁 bcrypt/argon2。
7. **依赖升级（H-6）**：`python-jose 3.3.0`→3.4+（或迁 pyjwt），`vite@5`→修订版。
8. **TLS 校验（H-3）**：生产把 `verify=False` 改为加载内网 CA bundle。

## 8. 部署步骤

```bash
# 1) 准备镜像（交付方预构建导出的 tar）
#    并确保客户 MySQL 已起、库+账号已建

# 2) 首次运行：生成 backend.env（含随机密钥），按提示填必填项
cd <repo>
IMAGE_TAR=/path/apaas-builder.tar ./deploy/customer/deploy.sh
#    → 编辑 /data/apaas/backend.env，填好所有 __SET_ME__（DB/aPaaS/LLM）

# 3) 再次运行：校验通过 → 拉起容器 → 健康检查 → seed 管理员
IMAGE_TAR=/path/apaas-builder.tar ./deploy/customer/deploy.sh

# 4) 配置前置 nginx（参考 deploy/docker/nginx.conf.example + §7 安全头），指向 :8003
```

## 10. 已知限制（交付时需告知客户）

- **单进程**：`platform_proxy` 全局状态导致后端 `--workers 1`，**不能多 worker 横向扩**，高并发需另设计。
- **无 Alembic**：schema 靠 `create_all` + 手写 `ALTER TABLE` 演进，跨大版本迁移无回滚机制。
- **27 处「假功能」**：部分设计器写操作按钮为占位（alert/disabled），详见 [测试用例](07-测试用例.md) 已知失败清单。
- **2 个不可修阻塞**：apaas 原生编辑器内嵌偶发崩、表单权限写入会破坏读端数据（详见测试用例 KB-01/KB-02）。
- **依赖 aPaaS**：不接 aPaaS 平台时，应用上线/平台代理等核心能力不可用（产品无价值）。
