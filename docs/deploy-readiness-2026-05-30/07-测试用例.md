## 一、概述

### 1.1 测试范围

本文档覆盖三个测试层次：

| 层次 | 工具 | 覆盖对象 |
|------|------|---------|
| **单元/集成自动化** | pytest 9.0.3 | 后端业务逻辑：Auth、Spec、Git、Proposal、应用管理、MCP 工具注册 |
| **API 接口测试** | httpx / curl / Postman | 177 个后端 HTTP 端点的关键路径 |
| **端到端 / UI 手工** | 浏览器人工执行 | 24 个核心用户流程（T1–T24） |

**不在范围内**：

- 前端单元测试（当前零覆盖，纯手工 UI 验收）
- 性能压测（独立专项）
- 安全渗透测试（独立专项，P0 待查 auth.py SSRF 暴露面）

### 2.3 11 个失败用例分析（全部为测试欠债，非生产 Bug）

> **结论**：11 个失败均为测试代码未跟进生产代码演进，不代表生产功能有 Bug。但它们导致部分关键路径（JWT auth、MCP 工具注册完整性）无法被测试覆盖，属于**测试债务**，建议在下一个迭代修复。

#### A 类：JWT audience 字段未同步（4 个）

| 用例 ID | 测试文件 | 失败原因 |
|---------|---------|---------|
| F-A1 | `test_auth_switch_tenant.py::test_switch_tenant_signs_new_token_for_member` | `jose.exceptions.JWTClaimsError: Invalid audience` |
| F-A2 | `test_auth_switch_tenant.py::test_platform_admin_can_switch_to_any_active_tenant` | 同上 |
| F-A3 | `test_platform_admin_tenant_context.py::test_platform_admin_login_token_uses_default_tenant` | 同上，另外 `AttributeError: 'dict' has no attribute 'id'` |
| F-A4 | `test_platform_admin_tenant_context.py::test_platform_admin_legacy_token_resolves_default_tenant` | 同上 |

**根因**：生产代码 `auth.py` 已在 JWT payload 加入 `aud` 字段，测试解码时未传 `audience` 参数，jose 校验拒绝。F-A3/F-A4 还存在把 `dict` 传给期望 `User` 对象参数的类型错误。

**修复建议**：
1. 测试 `decode(token, ...)` 时增加 `audience="apaas-builder"` 参数（或与生产值对齐）
2. 将 `create_access_token({"sub": user.id}, ...)` 改为传入 `User` ORM 对象

#### B 类：工具名称变更未同步（1 个）

| 用例 ID | 测试文件 | 失败原因 |
|---------|---------|---------|
| F-B1 | `test_section_hint.py::test_hint_contains_section_specific_tools` | 断言期望字符串 `list_application_dev_kits`，实际工具名已改为 `list_dev_scenes` |

**根因**：生产 MCP 工具从 `list_application_dev_kits` 重命名为 `list_dev_scenes`，对应的 section hint 文案已更新，但测试断言字符串未跟进。

**修复建议**：将测试断言中的 `list_application_dev_kits` 改为 `list_dev_scenes`（一行改动）。

#### C 类：FakeClient stub 接口落后（2 个）

| 用例 ID | 测试文件 | 失败原因 |
|---------|---------|---------|
| F-C1 | `test_step_executor_model_merge.py::test_execute_create_model_merges_existing_model_by_code_and_adds_missing_fields` | `FakeModelClient.query_models()` 不接受 `with_fields=` 关键字参数 |
| F-C2 | `test_step_executor_model_merge.py::test_execute_create_model_reuses_existing_field_by_code` | 同上 |

**根因**：生产代码 `step_executor.py:443` 已在调用 `query_models(with_fields=True)` 时新增 `with_fields` 参数，测试里的 `FakeModelClient` 实现未同步添加该参数。

**修复建议**：在 `FakeModelClient.query_models()` 方法签名加 `with_fields=False` 关键字参数（忽略即可，不影响 fake 返回逻辑）。

#### D 类：tool_registry.yaml 与 mcp_server.py 漂移（4 个）

| 用例 ID | 测试文件 | 失败原因 |
|---------|---------|---------|
| F-D1 | `test_tool_registry.py::test_config_whitelist_matches_current_expected` | config agent 白名单快照（62 工具）未更新，实际新增 16 个工具 |
| F-D2 | `test_tool_registry.py::test_yaml_matches_mcp_server_source` | `mcp_server.py` 注册了 4 个工具在 YAML 中缺 entry |
| F-D3 | `test_tool_registry.py::test_runtime_drift_check_passes_in_clean_state` | 同上，4 个真实漂移被 drift 检测拦截 |
| F-D4 | `test_tool_registry.py::test_runtime_drift_check_warns_when_yaml_has_extra` | 同上，前置条件里已存在 4 个真实漂移 |

**漂移的 4 个工具**（已在 `mcp_server.py` 注册但 `tool_registry.yaml` 缺 entry）：
- `get_apaas_form_detail`
- `get_apaas_process_detail`
- `list_apaas_app_processes`
- `set_role_resource_permission`

**修复建议**：
1. 在 `tool_registry.yaml` 补充上述 4 个工具的 entry（category、description、agent 白名单分配）
2. 更新 `_EXPECTED_CONFIG_WHITELIST` 快照（62 → 78 个工具，加入新的 dev_workspace 工具等）
3. drift 检测测试（F-D3/F-D4）会在 F-D2 修复后自动通过

### 2.4 收集错误（1 个，真 Bug）

| 文件 | 错误 | 性质 |
|------|------|------|
| `tests/test_spec_section_o1.py` | `ImportError: cannot import name 'SpecSection' from 'app.models'` | **真小 Bug**：`app/models/spec_section.py` 定义了 `SpecSection` 类，但 `app/models/__init__.py` 未 re-export；测试写 `from app.models import SpecSection` 失败 |

**修复建议**：在 `backend/app/models/__init__.py` 加一行：
```python
from app.models.spec_section import SpecSection  # noqa: F401
```
修复后可去掉 `--ignore=tests/test_spec_section_o1.py`。
