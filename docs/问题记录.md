## 优化项

### [OPT-001] brainstorm 意图分类改用 function call

**问题描述**

用户确认设计方案后，系统一直输出新的确认单而不生成代码。

**根本原因**

`_classify_brainstorm_response()` 调用 LLM 判断用户意图时，依赖文本匹配（找 `CONFIRM` / `REVISE` / `ABORT` 关键词），兜底逻辑是 `revise`。当 LLM 返回中文或格式不规范时，匹配失败默认走 revise，触发新一轮确认单，陷入循环。

**当前修复**（已上线）

- 加了关键词快速判断，用户说"好的/可以/确认/开始"等直接走 confirm，不经过 LLM
- 兜底逻辑从 `revise` 改为 `confirm`，避免死循环

**优化方向**

改用 function call（tool use），模型被强制返回 enum 值，彻底消除格式解析问题：

```python
tools = [{
    "type": "function",
    "function": {
        "name": "classify_intent",
        "parameters": {
            "type": "object",
            "properties": {
                "intent": {"type": "string", "enum": ["confirm", "revise", "abort"]}
            },
            "required": ["intent"]
        }
    }
}]
```

**前提条件**

租户配置的模型需支持 function call。部分国产模型（如 Qwen 某些版本）支持度不一致，需做兼容降级处理（不支持时回退到当前关键词方案）。

**相关文件**

- `backend/app/coding/pipeline.py` — `_classify_brainstorm_response()` / `_brainstorm_llm_call()`
