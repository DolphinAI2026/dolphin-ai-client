结论与建议

如果要给人或给 agent 讲清楚，现在最重要的是把“真实可调工具”和“旧文档口径”分开。

当前应认定的真实现状

  • 全量兼容入口是 /api/mcp/mcp，当前真实 42 工具。
  • 新拆分入口现在是 Builder 14、Coding 23、Vibe 9、Design 4。
  • Builder 仍以配置态为主，但已补回应用级 republish_apaas_app。
  • Coding 除了 publish_dev_workspace 外，也重新暴露了 enable / attach / republish / menu / upload 这些原子发布动作。

最值得提醒的差异

  • 历史“49 工具”是 2026-05-11 的验证口径，不等于今天代码现状。
  • ai-builder-coding-workflow.md 已同步为 23 工具；配置态文档同步为 14 工具。
  • 很多旧工具不是简单消失，而是被 save_design_draft、get_dev_scene、get_apaas_app_overview、get_apaas_form_detail 这些合并入口吸收了。
  • vibe_* 现在是“双注册”：既在 legacy full，也在独立 mcp_vibe。
如果后续要继续维护这页，建议以这 4 处代码为唯一事实源： backend/app/mcp_server.py、 backend/app/vibe_coding_mcp.py、 backend/app/design_mcp.py、 backend/app/main.py。 历史文档只保留做“版本差异”参考，不再反向推导现状。
